# 구조화 매매 전 점검

## 역할

이 SKILL은 주가를 예측하거나 목표가격을 맞히지 않는다. 검증된 입력을
`scripts/trade_check.py`에 전달하고 아래 네 상태 중 하나를 반환한다.

| 상태 | 의미 |
|---|---|
| `BLOCKED` | 불가능 주문, 안전 위반, 정책 위반, 오래되거나 손상된 핵심 데이터 |
| `RESEARCH_REQUIRED` | 승인 IPS 또는 검증된 논지·기대수익·대안 분석 부족 |
| `CAUTION` | 거래는 가능하지만 근거 또는 기회비용 재검토 필요 |
| `PROCEED` | 승인 정책과 검증 분석상 차단 사유 없음 |

`PROCEED`는 수익이나 가격 방향의 보장이 아니다.
CLI 종료 코드는 `PROCEED=0`, `CAUTION=1`, `RESEARCH_REQUIRED=2`,
`BLOCKED=3`이다. 자동화는 0 이외의 결과를 주문 가능으로 해석하면 안 된다.

## 필요한 입력

1. 보유내역 `knowledge/portfolio/holdings.csv`
   - 머리말에 기준일이 있어야 한다.
   - 평가금액은 KRW 환산 값이어야 한다.
2. 승인 IPS `knowledge/portfolio/ips.json`
   - `status: APPROVED`
   - 승인자·승인시각
   - 위험등급별 단일 종목 한도 (`standard_pct`와 `hard_ceiling_pct`)
   - 상위 10종목·섹터·통화·미분류 포트폴리오 한도
   - 데이터 최대 허용 지연
   - 예정가의 최대 허용 괴리 `data_quality.price_max_deviation_pct`
   - 기준가의 최대 허용 경과일 `data_quality.price_reference_max_age_days`
   - 시장별 비용·세금·슬리피지 가정 (`costs.by_market`)
   - 요구수익률과 대안 우위 기준
   - 기대수익 측정 기준 `decision_policy.return_measure`
   - 하방 예산 `decision_policy.max_bear_loss_contribution_pct`
3. 검증된 분석 JSON
   - `scripts/contracts.py`의 분석 계약을 통과해야 한다.
   - 모든 주장은 `claim_id`와 `source_ids`를 가진다.
   - 모든 분석은 `snapshot_id`와 입력 SHA-256을 가진다.
   - 논지, 반대 논지, 시나리오별 기대수익, 대안을 포함한다.
   - 시나리오는 약세·기준·강세 각각 **수익률·확률·근거 claim** 을 갖는다.
   - `calculation_id`가 계산 산출물 저장소의 산출물을 가리켜야 한다.
4. 계산 산출물 `knowledge/calculations/CALC-*.json`
   - `scripts/reverse_dcf.py`가 발급한다.
   - 분석의 시나리오 수익률이 이 산출물과 일치해야 한다.
5. 예정 수량·가격과 가격 기준시각
6. 예정가를 대조할 기준가
   - 1순위는 보유내역의 내재단가 `value_krw / quantity`. 정의상 기준통화
     환산값이라 환율 모호성이 없다.
   - 보유하지 않은 종목은 `scripts/price_fetch.py history`로 수집한
     시세 스냅샷. 스냅샷 통화가 기준통화와 다르면 환율을 지어내지 않고
     "대조 불가"로 처리한다.

하나라도 없으면 가격만 보고 빈칸을 채우지 않는다.

## 절차

### 1. 분석 계약을 먼저 검증한다

```bash
python3 scripts/validate_analysis.py analysis.json
```

검증 실패 분석은 저장하거나 매매 판단에 사용하지 않는다.

### 2. 구조화 엔진을 실행한다

```bash
python3 scripts/trade_check.py {asset_id} {buy|sell} {수량} \
  --price {KRW환산예정가} \
  --price-as-of {ISO-8601} \
  --ips knowledge/portfolio/ips.json \
  --analysis analysis.json \
  --calculations knowledge/calculations \
  --json
```

보유하지 않은 신규 종목이라 기준가가 없으면, 먼저 시세를 수집한다.

```bash
python3 scripts/price_fetch.py history {심볼}   # 214450.KQ / IBM
```

그래도 대조가 불가능한 경우에만 `--price-unverified-reason "{확인 경로}"`로
사유를 남긴다. 사유는 `CAUTION`으로 기록될 뿐 `PROCEED`를 만들지 않으며,
기준가와 어긋나는 가격은 사유로 해제되지 않는다.

### 3. 다섯 축을 모두 설명한다

- **논지 변화:** 강화·중립·약화·무효화와 근거 claim ID, 그리고 반대 논지
- **기대수익 범위:** 약세·기준·강세 각각의 수익률·확률·근거, 확률가중 기대수익,
  약세 손실이 총자산에서 차지하는 비중, 기간, 방법론, 요구수익률
- **포트폴리오 위험:** 총자산·주식 슬리브·위험자산 분모별 거래 전후 비중
- **세금·비용:** 수수료, 세금, 슬리피지, 환전비용
- **대안:** 같은 기간, **같은 측정 기준**의 대안과 전환 기회비용

가격대, 평단, 과거 같은 가격에서 했던 매매는 독립적인 매수·매도 근거로
사용하지 않는다.

## 기대수익을 무엇으로 재는가

IPS의 `return_measure`가 정한다.

| 값 | 판정에 쓰는 값 |
|---|---|
| `BASE` | 기준 시나리오 수익률 하나 |
| `PROBABILITY_WEIGHTED` | 세 시나리오의 확률가중 기대수익 |

`BASE`는 하방을 판정에서 제외한다. 하방이 -50%인 종목과 -5%인 종목이 기준
시나리오가 같으면 똑같이 통과한다는 뜻이다. 그래서 하방은 별도로 **하방 예산**이
막는다.

```
약세 손실 기여도 = 거래 후 포지션 × |약세 수익률| ÷ 총자산
```

이 값이 `max_bear_loss_contribution_pct`를 넘으면 `BEAR_LOSS_EXCEEDS_BUDGET`으로
차단한다. 시나리오의 깊이가 아니라 **깊이 × 비중**을 보므로, 같은 하방이라도
포지션이 작으면 통과하고 크면 막힌다.

대안은 포지션과 **같은 측정 기준**일 때만 비교한다. 기준이 다른 대안은
`ALTERNATIVE_MEASURE_MISMATCH`로 남기고 비교에서 제외한다.

## 무조건 차단

- 수량 또는 가격이 0 이하
- 보유량을 초과한 매도
- 예정가가 기준가 대비 IPS의 허용 괴리를 초과 (`PRICE_DEVIATION`)
- 대조할 기준가가 없는데 사유도 없음 (`PRICE_UNVERIFIED`)
- 기준가가 IPS의 허용 경과일 초과 (`PRICE_REFERENCE_STALE`)
- 매수금과 추정 비용이 현금을 초과
- 거래 후 비중이 위험등급의 절대 상한 초과 (`POSITION_HARD_CEILING`, 사유로도 해제 불가)
- 표준 한도 초과인데 집중 사유가 없음 (`POSITION_LIMIT_TOTAL_ASSETS`)
- 거래 대상의 위험등급에 대한 승인 한도가 IPS에 없음 (`RISK_CLASS_LIMIT_MISSING`)
- 거래 시장의 비용 모형이 IPS에 없음 (`COST_MODEL_MISSING`)
- 주식 슬리브·위험자산 한도가 설정돼 있는데 초과
- 이 거래가 포트폴리오 한도를 새로 넘기거나, 이미 넘긴 값을 더 악화
- 보유내역, 가격, 분석이 IPS의 신선도 기준 초과
- 종목과 분석 대상 불일치
- 분석 스키마 또는 출처·주장 ID 참조 오류
- 무효화 조건이 발생한 종목의 신규·추가 매수
- IPS가 차단하도록 정한 요구수익률 미달 매수
- 거래 후 약세 손실이 하방 예산 초과 (`BEAR_LOSS_EXCEEDS_BUDGET`)
- 분석의 시나리오 수익률이 계산 산출물과 불일치 (`CALCULATION_MISMATCH`)
- 계산 산출물이 없거나, 다른 종목 것이거나, 지문이 어긋남

## 위험등급과 2단계 한도

한도는 `asset_type`이 아니라 보유내역의 `risk_class`로 건다. ETF라는
껍데기는 위험을 말해주지 않기 때문이다.

| 등급 | 뜻 | 예 |
|---|---|---|
| `STOCK` | 개별 주식 | 파마리서치, IBM |
| `BROAD_ETF` | 광역 분산 ETF | SCHD (배당성장주 100여 종목, 연 1회 리밸런싱) |
| `DERIVATIVE_ETF` | 단일 기초자산 파생 ETF | MSTY (MSTR 100% 노출, 상승 캡·하락 그대로) |

각 등급은 두 값을 갖는다.

- `standard_pct` — 여기까지는 그냥 통과
- `hard_ceiling_pct` — 절대 넘지 못하는 선

표준과 상한 사이 구간은 기본 `BLOCKED`이고,
`--concentration-override-reason "{사유}"`로 사유를 남기면 `CAUTION`으로
통과한다. 사유는 결과 JSON과 결정 스냅샷에 함께 기록된다. 절대 상한은
사유로 해제되지 않는다.

등급이 IPS에 정의돼 있지 않으면 기본값으로 때우지 않고 `BLOCKED`다.

## 포트폴리오 집중도의 한계

엔진이 계산하는 섹터·통화·상위10 비중은 **ETF 룩스루를 반영하지 않은 직접
비중**이다. ETF가 품고 있는 섹터 노출은 `섹터 미분류`로 격리되며, 따라서
개별 섹터 비중은 언제나 하한이다. IPS의 `unclassified_total_assets_pct`가
이 사각지대의 크기를 제한한다. 실제 룩스루 집중도가 필요하면
portfolio-xray SKILL을 쓴다.

단일 종목 한도와 달리 포트폴리오 한도는 거래하지 않은 다른 종목 때문에도
초과할 수 있다. 이미 초과했다는 이유로 모든 거래를 막으면 위험을 줄이는
거래까지 불가능해지므로, 엔진은 **이 거래가 한도를 새로 넘기거나 이미 넘긴
값을 더 악화시킬 때만** `BLOCKED`로 처리하고, 악화시키지 않는 초과는
`CAUTION`으로 남긴다.

## 매수 해석

매수는 다음을 모두 만족해야 `PROCEED`가 가능하다.

- 논지가 사용자 승인 상태
- 무효화 조건 미발생
- IPS가 정한 측정 기준의 기대수익이 요구수익률 이상
- 거래 후 약세 손실이 하방 예산 이내
- 시나리오 수익률이 계산 산출물과 일치
- 더 나은 대안이 있다는 경고가 없음
- 거래 후 세 분모의 한도 이내
- 비용과 세금을 반영해도 현금 충분

근거 개수를 세지 않는다. 근거의 독립성, 인과성, 반증 가능성, 가치평가
민감도를 본다.

## 매도 해석

논지가 훼손되지 않았더라도 다음은 정당한 일부 매도 근거가 될 수 있다.

- 기대수익이 IPS 하한 아래로 하락
- 상승으로 집중 한도를 초과해 위험을 줄임
- 약세 손실이 하방 예산을 넘긴 포지션을 줄임
- 비용 차감 후 더 나은 대안이 존재
- 세금·현금수요·계좌 제약
- 이벤트 불확실성과 손실 예산 조정

엔진은 논지 훼손, 기대수익 하한 미달, 집중도 축소, 하방 예산 초과 축소,
대안 우위를 구조화된 `sell_drivers`로 반환한다. 드라이버가 없으면 `CAUTION`이다.

## 출력 형식

```
## 판정
BLOCKED | RESEARCH_REQUIRED | CAUTION | PROCEED

## 거래와 데이터 기준
수량 / 예정가 / 가격시각 / 보유기준일 / 분석 snapshot_id

## 예정가 검증
기준가 출처 / 기준가와 기준일 / 괴리와 허용 한도

## 포트폴리오 집중도
상위 10종목 / 섹터 / 통화 / 미분류 각각의 거래 전후 비중

## 비중
총자산 / 주식 슬리브 / 위험자산 각각의 분모와 거래 전후 비중

## 판단의 다섯 축
논지 / 기대수익 / 포트폴리오 위험 / 세금·비용 / 대안

## 기대수익
시나리오별 확률·연율·근거 / 판정에 쓴 값과 측정 기준 / 약세 손실 기여도 /
계산 산출물 ID

## 가장 강한 반대 근거
반대 논지와 반증 신호

## 차단·주의 사유
엔진의 issue code와 설명

## 결정 스냅샷
decision_snapshot_id
```

## 금지

- 가격대만으로 `PROCEED` 판정
- 대조하지 않은 예정가로 비중·현금 검사 통과
- 승인되지 않은 기본 비중 한도 사용
- 오래된 데이터를 최신인 것처럼 사용
- 출처 ID가 없는 주장을 매매 근거로 사용
- 계산 산출물 없이 손으로 적은 기대수익 사용
- 스키마 검증 실패 분석 저장
- 엔진의 `BLOCKED`를 자연어로 완화
