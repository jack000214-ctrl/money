# 매매 전 점검

## 이 SKILL이 하지 않는 것

**주가를 예측하지 않는다.** "오를 것 같다", "지금이 바닥이다" 같은 말을 만들지 않는다.

예측이 필요 없는 이유는 데이터에 있다. 파마리서치 검증(2026-07-26)에서 손실 241만원의
**91%가 예측 실패가 아니라 본인이 정한 규칙을 어긴 매도**에서 나왔다.
규칙 위반만 막아도 대부분이 걸러진다.

## 매도 이유의 유형을 기록한다 (판정하지는 않는다)

사용자 실측 데이터 — **표본 3개다. 결론을 내리기엔 부족하다.**

| 매도 유형 | 사례 | 결과 |
|---|---|---|
| 논지 기반 (엔비디아 투자철회) | 리커전 6.29·7.1 | +1,377,621원 |
| 가격 기반 (올라서 불안) | 파마리서치 6.15·6.25 | **-2,412,500원** |
| 가격 기반 (너무 빨리 오른다) | IBM 5.22 | **+317,356원** |

**가격 기반이 항상 나쁜 것이 아니다.** IBM이 반례다.
현재까지 말할 수 있는 것은 **가격 기반 매매의 분산이 크다**는 것뿐이다(-241만 ~ +32만).

따라서 이 SKILL은 가격 기반 매도를 **막지 않는다.** 대신 반드시 **유형을 기록**한다.
표본이 쌓여야 판정 기준이 생긴다. 지금 판정하면 3개 표본으로 만든 미신이 된다.

**단, 규칙 위반은 별개다.** 6.15 매도(306,500원)는 가격 기반이어서 문제가 아니라
**본인이 정한 매수 구간에서 팔았기 때문에** 문제였다. 그건 유형과 무관하게 잡는다.

## 절차

### 1. 계산을 먼저 돌린다

```bash
python3 scripts/trade_check.py {asset_id} {buy|sell} {수량} \
  --price {예정가} --buy-below {내 매수기준} --sell-above {내 매도기준}
```

비중 변화, 규칙 위반, 같은 가격대의 과거 매매가 나온다. **숫자는 이 출력에서만 인용한다.**

### 2. 회사 프로파일의 논지 상태를 읽는다

`knowledge/companies/{티커}-{이름}/profile.md` 의 무효화 조건 표를 확인한다.

- `TRIGGERED` 가 하나라도 있으면 → 매도 검토는 정당, 매수는 보류
- 전부 `SAFE` 인데 매도하려 한다면 → **가격 기반 매도일 가능성이 높다**
- `NOT_TESTED` 가 많으면 → 논지 자체가 미완성이다. 매매 전에 조사가 먼저다

### 3. 매도라면 이유의 유형을 묻는다

> "이 매도의 이유는 (A) 논지 훼손입니까, (B) 가격/불안입니까?"

(B)이면 그대로 진행시키지 않는다. 다음을 되묻는다.

- 무효화 조건 중 켜진 것이 있는가
- 없다면, 왜 지금 파는가
- 3개월 전 같은 가격에서 이 종목을 샀는가 (스크립트가 보여준다)

### 4. 매수라면 근거의 검증 가능성을 묻는다

> "이 매수 근거 중 공시·재무·계약으로 확인 가능한 것은 몇 개입니까?"

검증 불가능한 근거("시장이 아직 몰라준다", "섹터가 좋아질 것 같다")는 **개수에서 뺀다.**
파마리서치 매수 이유 9개 중 검증 가능한 것은 2개였다.

**급락 당일 매수는 재검토 후로 미룬다.** 2026-02-05 어닝쇼크 당일 395,000원 매수 사례가 있고,
그 어닝쇼크는 나중에 계절성으로 밝혀졌다 — 재검토했다면 판단이 달라졌을 자리다.

### 5. 분할 매도 요청이면

분할은 "얼마씩 파느냐"의 문제가 아니라 **"왜 파느냐"의 문제**다.
논지가 깨졌으면 분할할 이유가 없고, 안 깨졌으면 팔 이유가 없다.

분할이 정당한 경우는 둘뿐이다.

- **비중 조정** — 한도 초과분을 줄인다. 목표 비중을 먼저 정하고 거기까지만 판다
- **유동성 제약** — 한 번에 팔면 체결가가 나빠지는 규모

둘 다 아니면 분할 매도는 "팔고 싶은데 확신이 없다"의 다른 표현이다.

## 출력 형식

```
## 점검 결과
(스크립트 출력의 비중 변화와 규칙 판정)

## 논지 상태
(무효화 조건 중 SAFE / WARNING / TRIGGERED 개수와 내용)

## 이 매매의 유형
논지 기반 | 가격 기반 | 비중 조정 | 판단 불가

## 같은 가격대에서 과거에 한 일
(스크립트 출력)

## 판정
PROCEED | CAUTION | RULE_VIOLATION | RESEARCH_REQUIRED
+ 한 줄 이유

## 실행 후 기록할 것
knowledge/portfolio/trades/{asset_id}.csv 에 추가할 행
```

## 매매 후

**체결됐으면 즉시 거래내역에 기록한다.** `knowledge/portfolio/trades/{asset_id}.csv` 에
날짜·방향·수량·단가와 **그때의 이유**를 note 에 남긴다.

이유를 남기지 않으면 나중에 논지 기반이었는지 가격 기반이었는지 알 수 없고,
그러면 이 SKILL의 근거 데이터가 쌓이지 않는다.

## 금지

- 목표주가 제시
- "지금이 저점/고점" 같은 표현
- 무효화 조건 없이 매도를 승인
- 비중 한도 초과 매수를 그냥 통과
- 거래내역 기록 없이 매매를 끝내기
