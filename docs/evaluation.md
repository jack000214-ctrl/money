# 평가와 기억

## 목적

모델은 장기 저장소가 없고 시간이 지나며 교체된다. 따라서 좋은 모델을 전담 CIO로
만드는 자산은 대화 기록이 아니라 다음 세 묶음이다.

- 그때 모델이 실제로 본 context
- 모델·prompt 버전이 포함된 사전 판단
- 사후 가격 경로와 트리거로 계산한 evaluation

평가는 좋은 결과만 선별하는 백테스트가 아니라, 모든 사전 판단이 시간이 지나
얼마나 맞았는지 같은 정의로 측정하는 과정이다.

## 저장 계층

| 위치 | 내용 |
|---|---|
| `knowledge/contexts/<asset_id>/` | 가격·금액·기준시점별 입력 스냅샷 |
| `knowledge/assessments/<asset_id>/` | 계약을 통과한 모델 판단 |
| `knowledge/quarantine/<asset_id>/` | 계약 실패 모델 출력과 오류 |
| `knowledge/evaluations/<asset_id>/` | 이후 가격으로 산출한 평가 |

각 context와 assessment는 내용 지문 ID를 가진다. 같은 판단을 다시 저장해도 같은
내용이면 중복 자산을 만들지 않는다. 공식 판단은 덮어쓰지 않고 새 context와 새
assessment로 남긴다. 당시 근거와 prompt/schema도 내용 주소형 snapshot으로 보존하며,
읽을 때 지문을 다시 검사한다.

## 판단 저장

```bash
python3.13 -m cio record decision.json
```

`record`는 저장 전에 decision 계약을 다시 검증한다.

- 유효하면 `CIO-...` assessment ID를 발급해 공식 기억에 저장한다.
- 유효하지 않으면 원본 출력과 오류를 `INVALID-...` 파일로 격리한다.

격리 기록은 투자 판단에 재사용하지 않지만 버리지 않는다. 어떤 모델이 어떤
필드·산술·근거를 자주 실패하는지 평가하는 데이터다.

## 가격 기반 사후 평가

```bash
python3.13 -m cio score <asset_id>
```

`score`는 저장된 각 assessment에 대해 입력 기준일부터 평가 기간까지의 가격을
읽고 다음을 기록한다.

- 평가 기간 완료 여부
- 입력 가격 대비 기간 종료·최신 수익률
- 기간 중 최대 상승과 최대 하락
- 승리·실패 수익률 문턱 충족 여부
- 손절, 분할매도 시작, 재질문 하단·상단의 최초 도달일
- 승리 확률의 Brier score
- 확률가중 기대수익과 실제 수익률의 오차
- 보유분 행동의 두 다리 관측(아래)

### 매도는 두 다리로 나눠 본다

분할매도는 하나의 판단이 아니라 두 개의 베팅이다. 판 수량은 "앞으로 안 오를
것"에, 남긴 수량은 "오를 것"에 걸었다. 하나로 합치면 어느 쪽이 맞았는지 알 수
없으므로 `action.sold_leg`와 `action.retained_leg`를 따로 기록한다.

매도 다리는 **부호가 반대다.** 판단가 대비 이후 가격이 오르면 판 쪽은 기회를
놓친 것(`MISSED_GAIN`)이고, 내리면 손실을 피한 것(`AVOIDED_LOSS`)이다. 이 반전
없이 매수용 수익률을 그대로 쓰면 좋은 매도가 전부 패배로 기록되고, 시스템은
"위험 축소는 나쁜 것"을 스스로 학습한다.

매도에 승패 문턱을 두지 않는 이유는 계약에 매도용 문턱이 없기 때문이다. 임의의
기준선을 만드는 대신 방향과 크기만 남긴다.

### 사유별로 나눠 집계한다

`sell_reason_tier`가 `JUDGMENT`인 매도와 `CONSTRAINT`인 매도를 **절대 같은 통에
넣지 않는다.** 가격 예측력과 위험 관리 비용은 다른 것이며, 섞으면 둘 다 읽을 수
없게 된다. 제약 때문에 판 건이 평균적으로 손해라는 결과는 모델이 틀렸다는 뜻이
아니라 그것이 위험을 줄이는 값이라는 뜻이다. 회고에서는 사유별 승률과 평균
수익률을 나란히 놓고, 제약 매도가 실제로 값어치를 했는지 기록으로 판단한다.

기간이 끝나지 않았으면 승패와 Brier score를 확정하지 않는다. 가격 트리거는
일별 고가·저가를 주식분할 보정해 관측하고 기간 수익률은 조정종가를 사용한다.
일봉만으로 판단 시각 전후를 나눌 수 없으므로 판단 당일 봉은 제외하고 다음
거래일부터 관측한다.
평가 기준은 자산 통화 총수익률이며 환율·세금·수수료·슬리피지는 포함하지 않는다.

## 정성 평가

현재 `score`가 자동으로 평가하는 것은 가격과 숫자 문턱이다. 다음은 정기 회고에서
별도로 확인해야 한다.

- 가장 강한 반대 논지가 실제 핵심 위험이었는가
- 무효화 신호가 가격보다 먼저 관측됐는가
- 모델의 추가 조사 요청이 중요한 누락을 잡았는가
- 자산에 맞는 방법론과 가정을 선택했는가
- 배당, 세금, 환율, 기업행동 등 가격 시계열 밖 요인이 결과를 바꿨는가
- 사용자가 실제로 실행했는지와 실행 가격이 달랐는가

모델 verdict의 품질과 사용자의 실행 결과를 섞지 않는다. 모델은 제시 가격에서의
판단으로 평가하고, 실제 매매 성과는 별도 실행 기록이 있을 때만 비교한다.

## 모델·prompt 비교

assessment의 `model`에는 provider, name, version, prompt version이 들어간다.
충분한 완료 평가가 쌓이면 최소한 다음을 같은 시장·상품·기간끼리 비교한다.

- Brier score와 확률 구간별 실제 승률
- 기대수익 오차의 평균과 방향성
- 약세·기준·강세 범위 안에 실제 결과가 들어온 비율
- 손절·분할매도·재질문 가격의 도달률과 순서
- `INSUFFICIENT` 비율과 이후 확인된 중요 누락
- quarantine 비율과 오류 유형

표본이 적을 때 단일 수익이나 한 번의 적중으로 모델을 승격하지 않는다. 평가 정의나
prompt가 바뀌면 새 버전으로 기록하고 과거 결과를 다시 쓰지 않는다.

## 기억을 다음 판단에 쓰는 법

새 context에는 해당 자산의 최근 assessment digest만 포함한다. 모델은 과거 결론을
정답으로 복사하지 않고 다음을 비교한다.

- 당시 입력 가격과 현재 가격
- 당시 논지·반대 논지와 새로 확인된 사실
- 당시 재질문 가격·사건의 발생 여부
- 과거 확률과 실제 평가

전체 과거 파일은 필요할 때만 추가 조회한다. 이것이 기억을 자산으로 남기면서도
새 모델의 컨텍스트를 과거 문서로 소모하지 않는 기준이다.
