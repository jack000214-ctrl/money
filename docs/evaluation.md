# 평가와 기억

## 목적

과거 판단을 남기는 주된 이유는 **다음 판단과 시스템에서 무엇을 고칠지 찾기
위해서**다. 과거 판단은 존중할 비교 자료이며 현재 모델이 따라야 할 권위가 아니다.
현재 자료로 먼저 판단하고, 과거의 예상·실제 결과·실수를 대조한다. 더 나은 해석을
찾았다면 새로운 사건이 없어도 이전 결론을 폐기할 수 있다.

사용자와 모델의 판단을 함께 활용한 실제 수익과 사용 경험도 실용성의 평가 대상이다.
이를 모델 단독 성과라고 주장하지 않되, 분리된 모델 검증이 아직 부족하다는 이유로
실제 활용에서 얻은 가치를 무시하지 않는다. 실행 내역이 제공되기 전에는 사용자
후기를 임의의 거래·수익률 원장으로 변환하지 않는다.

모델은 장기 저장소가 없고 시간이 지나며 교체된다. 따라서 좋은 모델을 전담 CIO로
만드는 자산은 대화 기록이 아니라 다음 세 묶음이다.

- 그때 모델이 실제로 본 context
- 모델·prompt 버전이 포함된 사전 판단
- 사후 가격 경로와 트리거로 계산한 evaluation

평가는 좋은 결과만 선별하는 백테스트가 아니라, 모든 사전 판단이 시간이 지나
얼마나 맞았는지 같은 정의로 측정하는 과정이다.

## 저장 계층

| 위치 | 내용 |
|---|---|
| `knowledge/contexts/<asset_id>/` | 가격·금액·기준시점별 입력 스냅샷 |
| `knowledge/assessments/<asset_id>/` | 계약을 통과한 모델 판단 |
| `knowledge/quarantine/<asset_id>/` | 계약 실패 모델 출력과 오류 |
| `knowledge/evaluations/<asset_id>/` | 이후 가격으로 산출한 평가 |

각 context와 assessment는 내용 지문 ID를 가진다. 같은 판단을 다시 저장해도 같은
내용이면 중복 자산을 만들지 않는다. 공식 판단은 덮어쓰지 않고 새 context와 새
assessment로 남긴다. 당시 근거와 prompt/schema도 내용 주소형 snapshot으로 보존하며,
읽을 때 지문을 다시 검사한다.

## 판단 저장

```bash
python3.13 -m cio record decision.json
```

`record`는 저장 전에 decision 계약을 다시 검증한다.

- 유효하면 `CIO-...` assessment ID를 발급해 공식 기억에 저장한다.
- 유효하지 않으면 원본 출력과 오류를 `INVALID-...` 파일로 격리한다.

격리 기록은 투자 판단에 재사용하지 않지만 버리지 않는다. 어떤 모델이 어떤
필드·산술·근거를 자주 실패하는지 평가하는 데이터다.

## 가격 기반 사후 평가

```bash
python3.13 -m cio score <asset_id>
```

`score`는 저장된 각 assessment에 대해 입력 기준일부터 평가 기간까지의 가격을
읽고 다음을 기록한다.

- 평가 기간 완료 여부
- 입력 가격 대비 기간 종료·최신 수익률
- 기간 중 최대 상승과 최대 하락
- 승리·실패 수익률 문턱 충족 여부
- 손절, 분할매도 시작, 재질문 하단·상단의 최초 도달일
- 승리 확률의 Brier score
- 확률가중 기대수익과 실제 수익률의 오차
- 보유분 행동의 두 다리 관측(아래)
- 대안 행동 세 갈래의 반사실 비교(아래)

### `WAIT`은 안 샀는데 산 것처럼 재지 않는다

`price.return_to_end_pct`는 **질문가에서 시작하는** 수익률이다. `BUY_NOW`에는
맞지만 `WAIT`·`AVOID`에는 맞지 않는다 — 사지 않은 포지션의 수익률이기 때문이다.
그대로 쓰면 `WAIT` 뒤 오른 건은 전부 실패로, 내린 건은 전부 성공으로 기록되는데
모델이 건 것은 "질문가보다 낮은 어딘가에서 산다"이지 "주가가 내린다"가 아니다.

그래서 `counterfactual`이 같은 판단을 세 갈래로 나눠 잰다.

| 갈래 | 뜻 |
|---|---|
| `bought_at_ask` | 질문가에 즉시 샀다면. `price.return_to_end_pct`와 같은 값 |
| `waited_for_entry` | 제안 진입가에 걸어두고 기다렸다면 |
| `held_cash` | 현금이었다면. 자산 통화 명목 0% |

**`waited_for_entry.filled`가 먼저다.** 체결되지 않았다면 수익률이 나쁜 것이
아니라 **포지션이 없었던 것**이고, 그때 `return_to_end_pct`는 `null`이다.
계획이 실행되지 못한 것과 실행됐는데 틀린 것은 다른 사건이며, 섞으면 진입 계획의
품질을 읽을 수 없다. 체결 관측은 손절·분할매도와 같은 방식이다 — **진입가를**
분할 보정해 일봉 저가와 대조하고, **판단 당일 봉은 제외한다.** 진입가는 `preferred_entry`를
쓰고 그것이 없을 때만 `entry_range_high`로 내려가며, 어느 쪽을 썼는지는
`entry_price_basis`에 남는다(범위 상단이 먼저 체결되므로 더 관대한 기준이다).

이 평가는 **한 가격의 진입 대기**만 관측한다. 모델이 문장에 남긴 분할매수의
각 단계 금액과 실적·납입 조건은 평가하지 않는다. 따라서 이 값을 전체 분할매수
전략의 수익률이나 실행 여부로 제시하지 않는다.

구조화된 `entry_plan`이 있으면 단계별 가격 접촉과 모델의 조건 확인이 기록된 뒤의
접촉을 따로 낸다. 확인 기록은 다음날부터 사용하고, 기록이 없거나 주식단위가 맞지
않으면 실행 가능했다고 가정하지 않는다. 실제 집행은 UNKNOWN이고 전체 전략 수익률은
null이다. 이 경로에서는 단일 진입가의 「체결됨」 화면을 전체 계획 대신 보여주지 않는다.
[상세 계약](advisory-plans.md).

`advantage_pct`는 `bought_at_ask` 대비 차이이며 미체결이면 현금 대비로 계산된다.
**이것은 부등호 비교이지 판정이 아니다.** 어느 대안이 옳았는지는 여기서 정하지
않는다.

`price.return_to_end_pct`와 `fixed_horizons`의 기준점은 **바뀌지 않았다.** 그쪽은
모델 승격 비교가 쓰는 고정된 자이고, 진입가 기준으로 옮기면 모델마다 다른
시작점에서 재게 되어 고정 기간 평가가 존재하는 이유가 사라진다. 반사실은
대체가 아니라 덧붙임이다.

### 매도는 두 다리로 나눠 본다

분할매도는 하나의 판단이 아니라 두 개의 베팅이다. 판 수량은 "앞으로 안 오를
것"에, 남긴 수량은 "오를 것"에 걸었다. 하나로 합치면 어느 쪽이 맞았는지 알 수
없으므로 `action.sold_leg`와 `action.retained_leg`를 따로 기록한다.

매도 다리는 **부호가 반대다.** 판단가 대비 이후 가격이 오르면 판 쪽은 기회를
놓친 것(`MISSED_GAIN`)이고, 내리면 손실을 피한 것(`AVOIDED_LOSS`)이다. 이 반전
없이 매수용 수익률을 그대로 쓰면 좋은 매도가 전부 패배로 기록되고, 시스템은
"위험 축소는 나쁜 것"을 스스로 학습한다.

매도에 승패 문턱을 두지 않는 이유는 계약에 매도용 문턱이 없기 때문이다. 임의의
기준선을 만드는 대신 방향과 크기만 남긴다.

미래 `exit_plan` 단계는 판단을 기록한 시각의 시장 날짜 다음 거래일부터
유효기간 안에 일봉 고가가
지정가에 닿았는지만 별도로 관측한다. 모델이 후속 판단에서 조건을 확인했다면
그 기록 이후의 가격 접촉도 구분한다. 선행 매도·주문 제출·실제 체결은 가격
시계열로 알 수 없으므로 모두 `UNKNOWN`이며 단계별 매도 대금이나 전체 전략
수익률을 만들어 내지 않는다.

### 사유별로 나눠 집계한다

`sell_reason_tier`가 `JUDGMENT`인 매도와 `CONSTRAINT`인 매도를 **절대 같은 통에
넣지 않는다.** 가격 예측력과 위험 관리 비용은 다른 것이며, 섞으면 둘 다 읽을 수
없게 된다. 제약 때문에 판 건이 평균적으로 손해라는 결과는 모델이 틀렸다는 뜻이
아니라 그것이 위험을 줄이는 값이라는 뜻이다. 회고에서는 사유별 승률과 평균
수익률을 나란히 놓고, 제약 매도가 실제로 값어치를 했는지 기록으로 판단한다.

### 폐기된 판단도 채점한다

**폐기의 뜻은 "근거로 인용하지 않는다"이지 "그런 예측을 한 적이 없다"가 아니다.**
실제 날짜에 실제 가격에서 내린 예측이므로 맞았는지 틀렸는지는 여전히 측정 가능하다.

그래서 `score`는 `knowledge/assessments/`와 `knowledge/retired/`를 모두 읽는다.
평가 결과에는 `source: LIVE | RETIRED`와 `citable`이 붙고, 폐기 건에는 폐기 사유까지
함께 남는다. 두 통을 섞어 모델을 비교하지 않는다 — 그때의 계약과 prompt가 지금과
달랐기 때문이다.

**채점 계약과 인용 계약은 다르다.** 인용에는 현재 계약 전체가 필요하지만(안 그러면
모델이 낡은 의미론을 물려받는다), 채점에는 `SCORING_REQUIRED`만 있으면 된다 —
context·verdict·기간·승패 문턱·기대수익·가격계획. `drivers`나 `method`가 없어도
"그때 무엇을 예측했는가"는 계산된다.

둘을 하나로 묶으면 계약을 조일 때마다 track record가 통째로 사라진다. 계약을
개선할수록 과거를 잃는 구조는 "모델이 좋아질수록 강해지는 시스템"의 정반대다.

### 고정 기간 — 모델의 자기 선언과 무관하게

모델이 `horizon_months`와 승패 문턱을 스스로 정하면 **모델마다 다른 사건을
예측하게 된다.** 그러면 Brier score를 나란히 놓을 수 없고, 쉬운 문턱을 고르는
것만으로 점수가 좋아진다.

모델이 정한 기간은 설명용으로 유지하되, 모든 평가에 `fixed_horizons`가 함께
계산된다.

- `months.m1 / m3 / m6 / m12 / m24` — 요청 가격 대비 총수익률과 `complete` 여부
- `vs_benchmark.<symbol>.<horizon>.excess_pct` — 기준지수 대비 초과수익

기준점은 **판단일 시점의 지수**다. 판단일 이후 첫 봉을 쓰면 그날의 지수 움직임이
통째로 빠진다. `excess_pct`는 beta=1 가정의 단순 차감이며 위험조정 수익이 아니다.
`complete: false`인 값을 완료된 것과 같은 통에 넣지 않는다.

모델 승격 비교는 자기 선언 문턱이 아니라 이쪽을 쓴다.

기간이 끝나지 않았으면 승패와 Brier score를 확정하지 않는다. 가격 트리거는
일별 고가·저가로 관측하고 기간 수익률은 조정종가를 사용한다. 저장된 시계열은
이미 오늘 기준으로 분할이 반영돼 있으므로 **보정하는 쪽은 판단 시점 호가로 적힌
값**(손절가·진입가·질문가)이며, 시계열에도 같이 곱하면 두 번 조정되어 닿은 적
없는 손절가가 닿았다고 기록된다.
일봉만으로 판단 시각 전후를 나눌 수 없으므로 판단 당일 봉은 제외하고 다음
거래일부터 관측한다. 판단일은 요청 시각을 해당 자산의 시장 시간대(한국은 서울,
미국은 뉴욕)로 옮긴 날짜다. 한국 시각으로 날짜가 먼저 바뀐 미국 판단에서 첫
사후 거래일을 한 번 더 제외하지 않는다.
평가 기준은 자산 통화 총수익률이며 환율·세금·수수료·슬리피지는 포함하지 않는다.

## 정성 평가

현재 `score`가 자동으로 평가하는 것은 가격과 숫자 문턱이다. 다음은 정기 회고에서
별도로 확인해야 한다.

- 가장 강한 반대 논지가 실제 핵심 위험이었는가
- 무효화 신호가 가격보다 먼저 관측됐는가
- 모델의 추가 조사 요청이 중요한 누락을 잡았는가
- 자산에 맞는 방법론과 가정을 선택했는가
- 배당, 세금, 환율, 기업행동 등 가격 시계열 밖 요인이 결과를 바꿨는가
- 사용자가 실제로 실행했는지와 실행 가격이 달랐는가

모델 verdict의 품질과 사용자의 실행 결과를 섞지 않는다. 모델은 제시 가격에서의
판단으로 평가하고, 실제 매매 성과는 별도 실행 기록이 있을 때만 비교한다.

## 모델·prompt 비교

assessment의 `model`에는 provider, name, version, prompt version이 들어간다.
충분한 완료 평가가 쌓이면 최소한 다음을 같은 시장·상품·기간끼리 비교한다.

- Brier score와 확률 구간별 실제 승률
- 기대수익 오차의 평균과 방향성
- 약세·기준·강세 범위 안에 실제 결과가 들어온 비율
- 손절·분할매도·재질문 가격의 도달률과 순서
- `INSUFFICIENT` 비율과 이후 확인된 중요 누락
- quarantine 비율과 오류 유형

표본이 적을 때 단일 수익이나 한 번의 적중으로 모델을 승격하지 않는다. 평가 정의나
prompt가 바뀌면 새 버전으로 기록하고 과거 결과를 다시 쓰지 않는다.

## 기억을 다음 판단에 쓰는 법

새 context에는 해당 자산의 최근 assessment digest만 포함한다. 모델은 과거 결론을
정답으로 복사하지 않고 다음을 비교한다.

- 당시 입력 가격과 현재 가격
- 당시 논지·반대 논지와 새로 확인된 사실
- 당시 재질문 가격·사건의 발생 여부
- 과거 확률과 실제 평가

전체 과거 파일은 필요할 때만 추가 조회한다. 이것이 기억을 자산으로 남기면서도
새 모델의 컨텍스트를 과거 문서로 소모하지 않는 기준이다.
