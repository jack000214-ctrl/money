# 06. 앱 계층 설계

## 1. 앱의 역할

앱은 투자 엔진이 아니라 **상태 확인, 근거 검토, 사용자 수정, 승인**을 위한 개인 인터페이스다. 모든 핵심 계산과 정책 판정은 서버 계층에서 수행한다.

## 2. 제품 형태

### 제안

- 비공개 웹앱 또는 PWA
- 데스크톱에서 심층 분석, 모바일에서 알림과 간단 검토
- 초기 읽기 전용
- 단일 사용자 인증
- 배치 보고서와 동일 API 사용

네이티브 모바일 앱은 알림·생체인증·오프라인 기능의 필요성이 확인된 후 검토한다.

## 3. UX 원칙

### 확정

- 수익률보다 위험과 투자논지 상태를 먼저 보여준다.
- 색상만으로 좋음·나쁨을 판단하게 하지 않는다.
- 모든 숫자에 기준일, 통화, 단위를 표시한다.
- 추천에는 근거와 반대 근거를 같은 화면에 표시한다.
- 중요한 행동에는 충분한 마찰을 둔다.
- 정보가 없거나 오래됐으면 빈칸 대신 명확한 상태를 보여준다.
- 사용자가 매일 앱을 열도록 유도하는 게임화 요소를 넣지 않는다.

## 4. 정보 구조

| 영역 | 목적 | 주요 내용 |
|---|---|---|
| 홈 | 오늘 확인할 내용 | 중요 이벤트, 정책 경고, 다음 일정 |
| 포트폴리오 | 전체 자산 상태 | 배분, 성과, 집중도, 현금흐름 |
| 기업 | 종목별 연구 | 재무, 밸류에이션, 논지, 공시 |
| 리서치 | 후보 관리 | 관심목록, 미해결 질문, 비교 |
| 의사결정 | 제안 검토 | 근거, 반론, 비중, 무효화 조건 |
| 기록 | 과거 판단 감사 | 논지 버전, 승인, 결과, 회고 |
| 운영 | 데이터 상태 | 수집 상태, 신선도, 실패 작업 |
| 설정 | 정책·연동 | IPS, 계좌, 알림, 권한 |

## 5. 핵심 화면

### 5.1 홈

```text
오늘의 상태
├─ 즉시 검토할 사건
├─ 포트폴리오 정책 경고
├─ 데이터 신선도
├─ 다음 실적·공시 일정
└─ 변화 없음: NO_ACTION
```

시세 등락 목록보다 행동이 필요한 사건을 먼저 보여준다.

### 5.2 포트폴리오

- 총자산과 현금흐름을 분리한 수익률
- 기준지수 비교
- 자산·국가·섹터·통화 배분
- 상위 위험 기여 종목
- 목표 배분 이탈
- 수수료·세금·환전비용 추정
- 투자논지가 오래됐거나 없는 보유 종목

### 5.3 기업 상세

- 회사의 수익 구조 한 문장
- 최신 핵심 KPI
- 재무 추세와 현금흐름
- 밸류에이션과 시나리오
- 현재 투자논지
- 최근 공시가 논지에 미친 변화
- 반대 논거
- 무효화 조건
- 다음 확인 이벤트
- 원문 근거

### 5.4 의사결정 검토

- 제안 행동과 목표 비중 범위
- 현재 비중과 정책 한도
- 제안 근거와 반대 근거
- 기대 시나리오와 손실 시나리오
- 비용·세금·집중도 변화
- 데이터 기준시점
- 승인, 거절, 수정, 보류

실거래 기능이 도입되더라도 `분석 승인`과 `주문 승인`은 별도 단계다.

## 6. 사용자 피드백

사용자는 다음을 수정할 수 있다.

- AI 분석의 사실 오류 표시
- 투자논지 문구와 중요도
- 무효화 조건
- 관심 종목 상태
- 알림 중요도
- 제안된 비중
- 보류·거절 사유

피드백은 모델을 즉시 재학습시키지 않고 평가 데이터와 규칙 개선에 사용한다.

## 7. 상태 모델

### 분석

```text
DRAFT → REVIEWED → APPROVED → SUPERSEDED
              └→ REJECTED
```

### 의사결정

```text
RESEARCH_REQUIRED → WATCH → PROPOSED → APPROVED
                                  ├→ REJECTED
                                  └→ EXPIRED
```

### 주문

```text
DRAFT → RISK_CHECKED → USER_CONFIRMED → SUBMITTED → FILLED
                  └→ BLOCKED                       └→ PARTIAL/REJECTED
```

## 8. 알림

### 즉시 알림 후보

- 중요 정정공시
- 감사의견·거래정지·상장 관련 사건
- 투자논지 무효화 조건 후보
- 포트폴리오 한도 초과
- 주문 또는 계좌 동기화 이상

### 요약으로 묶을 항목

- 일반 가격 변동
- 낮은 중요도의 공시
- 관심 종목의 경미한 변화
- 정기 재무 업데이트

알림에는 “왜 지금 알리는지”와 필요한 다음 행동을 포함한다.

## 9. API 경계

앱은 다음 서비스만 사용한다.

- 포트폴리오 조회
- 기업·공시·분석 조회
- 투자논지 수정과 승인
- 추천 조회와 사용자 응답
- 운영 상태 조회
- 정책 조회와 변경 요청

클라이언트에서 재무비율, 추천 점수, 위험 한도를 다시 계산하지 않는다.

## 10. 보안

- 강한 단일 사용자 인증
- 민감한 설정 재확인
- 읽기와 주문 권한 분리
- 세션 만료와 기기 관리
- 민감한 계좌 식별자 마스킹
- 모든 승인·정책 변경 감사 로그
- 앱 번들에 API 비밀키 포함 금지

## 11. 접근성·설명 수준

- 투자 용어에 짧은 설명과 용어집 링크
- 수치의 계산 방식 보기
- 초보 설명과 상세 분석 전환
- 모바일에서도 근거와 반론을 생략하지 않음

## 12. MVP 제외 범위

- 실시간 호가창
- 소셜 피드
- 커뮤니티 순위
- 고빈도 차트 도구
- 완전 자동 주문
- 공개 회원가입과 다중 사용자
- 수익률 게임화

## 13. 검토가 필요한 결정

- 로컬 웹앱 또는 개인 클라우드
- 모바일 푸시 필요 여부
- 첫 화면에서 성과와 위험의 배치
- 사용자 수정 내용을 공식 논지로 승격하는 절차
- 주문 승인 UX 도입 시점
