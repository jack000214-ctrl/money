# 13. 아키텍처 결정 기록

## 1. 사용법

이 문서는 중요한 결정을 한곳에 기록한다. 결정이 바뀌면 과거 행을 삭제하지 않고 상태와 대체 결정을 추가한다.

### 상태

- `PROPOSED`: 검토 중
- `ACCEPTED`: 현재 적용
- `SUPERSEDED`: 새 결정으로 대체
- `REJECTED`: 검토 후 채택하지 않음

| ADR-028 | ACCEPTED | 국내 매도세는 실제 보유 종목의 시장(코스닥 20bp)을 기준으로 건다 | 코스피는 15bp라 코스피 매수 시 5bp 과대계상되지만, 과대 방향은 한계 거래를 막는 쪽이라 안전 |
| ADR-029 | ACCEPTED | 미국 양도소득세는 거래 단위 비용에 넣지 않는다 (`sell_tax_bps` = 0) | 연 250만원 공제 후 연간 정산이라 거래마다 떼지 않음. 넣으면 매 거래가 부풀려짐 |
| ADR-030 | ACCEPTED | 환전 스프레드는 편도 25bp. 두 우대구간의 혼합 가정이며 실측이 아니다 | 토스 우대율은 정규시간(9:10~15:20) 95%, 시간외 50%다. 기준 스프레드는 2026-07-17 같은 날 환전 두 건의 51.6bp 격차에서 역산했다(51.6÷0.45≈115bp, 통상 1% 수준). 따라서 정규 5bp / 시간외 50bp이고 둘을 섞어 쓰므로 중간값 25bp를 쓴다. 내역서는 적용환율만 찍고 기준환율을 안 남겨 직접 역산은 불가하다 |
| ADR-031 | ACCEPTED | 섹터 한도는 직접비중 기준 35% (실질 룩스루 40% 부근을 겨냥) | 엔진이 보는 값은 ETF 룩스루 미반영 직접비중이라 항상 하한. 파마리서치와 RXRX가 같은 헬스케어라는 사실을 강제로 인식시키는 장치 |
| ADR-032 | ACCEPTED | `unclassified_total_assets_pct`는 걸지 않는다 | 미분류는 위험이 아니라 룩스루 미구현이라는 데이터 공백이다. 한도를 걸면 보유 자산 중 가장 분산된 SCHD 매수가 먼저 막히는 역설이 생긴다. 위험 축은 이미 `risk_class`가 분리한다(SCHD=BROAD_ETF 50%, MSTY=DERIVATIVE_ETF 5% 하드캡). 사각지대 크기도 그 상한들로 이미 묶여 있다 — 숨은 헬스케어 최대 9.4%p |
| ADR-033 | ACCEPTED | 위험자산·통화·상위10 한도는 걸지 않는다 | 현금 4천만은 '대기자금'이라 주식 비중 상한을 걸면 대기자금 정의와 모순된다(ADR-024). 통화는 USD 48.67%로 거의 5:5라 편중이 아니고, 통화로 종목 선택을 제약하는 건 주객전도. 상위10은 보유가 6종목뿐이라 위험자산 총량과 같은 값이 된다 |
| ADR-034 | ACCEPTED | 기대수익은 승인된 계산기의 산출물에서만 온다. `calculation_id`는 모델·입력·산출값 전체의 SHA-256 지문 | 출처 없는 주장은 매매 근거로 못 쓰게 막아놓고, 정작 매매를 결정하는 유일한 숫자(`base_pct`)는 근거 없이 손으로 적을 수 있었다. 촘촘한 울타리 한가운데 열린 문. 입력만 지문화하면 가정을 그대로 두고 결과 숫자만 고칠 수 있어 산출값도 포함한다 |
| ADR-035 | ACCEPTED | 시나리오는 약세·기준·강세 각각 확률과 근거 claim을 갖는다. 확률 합 1, 확률 0 금지 | 07번 문서 §6이 `probability: calibrated_estimate`를 요구했으나 계약에 없어 아무도 쓰지 않았다. 근거 없는 bear는 숫자일 뿐이라 아무 값이나 적어도 통과했다 |
| ADR-036 | ACCEPTED | 하방은 `깊이 × 비중`으로 예산을 건다 (`max_bear_loss_contribution_pct`) | 판정이 `base_pct` 하나로 이뤄져 `bear_pct`는 계약 검증만 통과하면 그만이었다. 하방 -50%와 -5%가 기준 시나리오만 같으면 똑같이 통과했다. 예산을 비중과 곱해 걸면 07번 §9의 "하방 시나리오의 손실 허용 범위로 1차 비중을 계산한다"가 구속력을 갖는다 |
| ADR-037 | ACCEPTED | 기대수익 측정 기준을 IPS가 고른다 (`return_measure`). 대안은 같은 기준일 때만 비교 | 기준을 섞으면 비교가 성립하지 않는다. 어느 자로 재는지가 판정을 바꾸므로 정책이 정해야 하고, 코드 기본값으로 숨기지 않는다 |
| ADR-038 | ACCEPTED | `counter_thesis`(가장 강한 반대 근거)와 관측 가능한 반증 신호를 계약 필수로 | 07번 §8이 추천 필수 항목으로 정해 놓았으나 계약에 필드가 없어 실제로는 아무도 쓰지 않았다. 약한 반론을 세우고 이기면 아무것도 검증되지 않는다 |
| ADR-039 | ACCEPTED | 시나리오 수익률은 연율. 총수익률은 참고로만 표시 | IPS 요구수익률이 연율이라 같은 자로 재야 비교가 된다. 24개월 +40%와 12개월 +40%를 같은 값으로 취급하면 기간이 긴 논지가 자동으로 유리해진다 |
| ADR-040 | ACCEPTED | FCF가 음수인 기업에는 정률성장 DCF를 쓰지 않고 `RESEARCH_REQUIRED` | 적자 기업에서 성장률을 올리면 가치가 낮아지는 값이 나온다. 모델이 성립하지 않는 구간에서 숫자를 뽑으면 그 숫자가 판정에 들어간다. RXRX가 이 경우다 |

## 4. 현재 권장 기본안

아래 값은 확정된 투자 권유가 아니라 구현 범위를 줄이기 위한 제안이다.

- 한국 시장부터 시작
- ETF와 보유 중인 개별주를 모두 읽되 신규 액티브 추천은 모의운용
- 계좌 CSV 가져오기를 먼저 만들고 읽기 전용 API를 추가
- 장 마감 일봉 중심
- DART 공시와 분기 재무 중심
- 로컬 또는 개인 전용 서버
- 첫 SKILL은 기업 투자논지 추적기
- 첫 앱은 읽기 중심 PWA
- 실거래는 단계 5 이전 제외

## 5. 문서별 검토 체크리스트

- [ ] 제품의 목표와 비목표가 맞는가
- [ ] 투자 대상과 기간을 기입했는가
- [ ] 감내 가능한 손실 한도를 정했는가
- [ ] 배치·SKILL·앱의 역할 분리가 맞는가
- [ ] AI에게 더 주거나 덜 줘야 할 권한이 있는가
- [ ] 첫 전략 후보가 사용자의 관심과 맞는가
- [ ] 앱에서 가장 먼저 보고 싶은 화면이 맞는가
- [ ] 데이터 소스와 증권사가 현실적인가
- [ ] 로컬·클라우드 선호가 반영됐는가
- [ ] 자동매매 도입 기준에 동의하는가
