# 13. 아키텍처 결정 기록

## 1. 사용법

이 문서는 중요한 결정을 한곳에 기록한다. 결정이 바뀌면 과거 행을 삭제하지 않고 상태와 대체 결정을 추가한다.

### 상태

- `PROPOSED`: 검토 중
- `ACCEPTED`: 현재 적용
- `SUPERSEDED`: 새 결정으로 대체
- `REJECTED`: 검토 후 채택하지 않음

## 4. 현재 권장 기본안

아래 값은 확정된 투자 권유가 아니라 구현 범위를 줄이기 위한 제안이다.

- 한국 시장부터 시작
- ETF와 보유 중인 개별주를 모두 읽되 신규 액티브 추천은 모의운용
- 계좌 CSV 가져오기를 먼저 만들고 읽기 전용 API를 추가
- 장 마감 일봉 중심
- DART 공시와 분기 재무 중심
- 로컬 또는 개인 전용 서버
- 첫 SKILL은 기업 투자논지 추적기
- 첫 앱은 읽기 중심 PWA
- 실거래는 단계 5 이전 제외

## 5. 문서별 검토 체크리스트

- [ ] 제품의 목표와 비목표가 맞는가
- [ ] 투자 대상과 기간을 기입했는가
- [ ] 감내 가능한 손실 한도를 정했는가
- [ ] 배치·SKILL·앱의 역할 분리가 맞는가
- [ ] AI에게 더 주거나 덜 줘야 할 권한이 있는가
- [ ] 첫 전략 후보가 사용자의 관심과 맞는가
- [ ] 앱에서 가장 먼저 보고 싶은 화면이 맞는가
- [ ] 데이터 소스와 증권사가 현실적인가
- [ ] 로컬·클라우드 선호가 반영됐는가
- [ ] 자동매매 도입 기준에 동의하는가
