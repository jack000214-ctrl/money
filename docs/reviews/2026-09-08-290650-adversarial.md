# 엘앤씨바이오 실제 분석 후 적대 리뷰 — 2026-09-08

이 문서는 최초 발견 기록과 사용자 검토 후 수정 결과를 함께 보존한다. 아래 1~6항의
「현재」「미해결」은 **최초 리뷰 당시**를 뜻한다. 이후 분할매수 제안의 예산·조건,
DART 유·무상증자의 주당 기준, 조건부 평가, 컨센서스 실패 처리를 보완했다.
최종 상태와 검증은 [후속 수정](#사용자-검토-후-후속-수정), 지원 범위는
[현재 계약](../advisory-plans.md)을 기준으로 읽는다.

최초 분석 당시에는 원문 보존과 산술 오류 방지에 유용했지만 분할매수 계획 전체와
기업행동 전후의 주당 기준을 검증할 수 없었다. 막힌 입력을 복구한 뒤 판단을 기록했으며,
아래 공격용 변조본은 공식 판단으로 저장하지 않았다. 기존 작업 트리의 변경을 유지했고
커밋·스테이징은 하지 않았다.

**1. [P1] 분할매수는 현재 계약의 보호 밖에 있다.**

[검증기](../../cio/decision.py)는 현재 집행액 `proposed_trade.amount`만 예산과 대조하고, `rationale`은 비어 있지 않은지만 검사한다. [사후평가](../../cio/memory.py)의 `_counterfactual`은 `preferred_entry` 한 가격을 사용한다. 단계별 금액·조건·취소·주식 단위를 저장하는 필드가 없다.

실제 검증을 통과한 WAIT 초안의 현재 집행액 0을 유지하고 이유만 「향후 1차 5000만원, 2차 5000만원, 3차 5000만원」으로 바꾸자 **검증 오류가 0개**였다. 구조화된 예산을 바꾼 것이 아니라 문장이므로 현재 검증기는 이를 읽지 않는다. 반대로 신규 [분할매수 산술 계산기](../../calculators/staged_entry.py)는 합계 예산 초과와 통화 혼합을 거부한다.

이번 실제 계획은 별도 계산기로 예산·정수주·무상 전후 단위를 계산하고 판단 문장과 별도 파일에 보존했다. 이 조치는 공식 `record → show → score`가 같은 계획을 검사한다는 뜻이 아니다. 다음 개선은 단계별 조건·예산·가격·권리 기준을 decision에 결속하고, 가격만으로 관찰 가능한 단계와 사업 조건 확인이 필요한 단계를 나누는 것이다. 기존 단일 진입가 평가를 분할매수 성과로 부르면 안 된다.

재현 출력: 로컬 `data/logs/290650-adversarial-probes.json`. 변조본은 `validate_decision(..., context=...)` 호출로만 검사했다.

**2. [P1] 희석 수치가 존재하는 것과 미래 희석을 반영한 것은 다르다.**

수집된 과거 EPS 분모는 26,438,908.97주다. 9월 2일 공시에 따른 증자 전 발행주식 26,969,704주, 자기주식 232,240주, 신규 유상주식 3,700,000주를 반영한 전망 분모는 30,437,464주다. 동일 순이익을 과거 분모로 나누면 이번 가정 대비 EPS를 약 **15.12% 높게** 보게 된다. 이는 주가 전망의 방향을 바꿀 수 있는 차이다.

초기 PASS packet은 `dilution.state=AVAILABLE`, `basis=null`인 동시에 「현재 시점의 희석주식수」라고 설명했다. 원본의 `eps_basis=DILUTED`를 `_latest_fundamentals`가 옮기지 않았기 때문이다. 게다가 회계상 희석 EPS는 미래 증자 후 완전희석 분모가 아니며, 적자일 때 반희석 증권이 제외될 수도 있다.

현재 [패킷](../../cio/context.py)은 EPS 종류와 주식 수 교차검증 값을 보존하고 「재무 보고기간의 EPS 분모」로 설명한다. 증자·권리락 공시가 보이면 가격·수량·납입·권리 자격을 원문으로 맞추라는 조사 요구도 붙인다. 그러나 이것은 한계를 알리는 보완이다. 발행·자기주식·전환증권·배정권·납입을 시점별로 구성하고 판정 가격과 결속하는 계약은 여전히 없다. 이번 가치평가에서는 모델이 공시의 미래 분모를 명시했다.

**3. [P1] 상세 위험을 담은 발행공시를 수집 정책에서 제외했다.**

기존 `DART_FILING_TYPES`는 A·B·I·F만 요청했다. C 유형인 증권신고서·투자설명서가 종목 공시 색인에서 빠졌다. `documents_for`는 공시 색인에 있는 접수번호로 종목 원문을 연결하기 때문에, `collectors.dart document 20260803000418`로 원문을 받아도 `cio search 290650 ... --doc DARTDOC:20260803000418`는 「원문이 없다」고 답했다.

이 회사에서는 투자설명서에 연결 품목별 매출, 원재료 공급처 집중, 중국 매출과 영업권, 자금 사용 기간이 있었다. 이 경로를 놓치면 가격 하락과 리투오 성장 기사만으로 추천을 정교화할 위험이 커진다.

[수집기](../../collectors/dart.py)에 C 유형을 추가하고 증권신고서·투자설명서를 중요 공시로 분류했다. 실제 재수집 후 9월 2일 투자설명서 `20260902000178`과 발행조건 정정 `20260902000144`가 검색된다. 기존 refresh 계약이 유형 목록을 비교하므로, 구형 필터로 만든 다른 한국 자산 색인은 다음 refresh에서 갱신 대상이 된다. 모든 한국 자산을 일괄 갱신하지는 않았다.

**4. [P1] 연결/별도 범위의 제한이 주석에만 있었다.**

기존 `resolve_shares`는 지배주주 순이익이 없으면 연결재무에서도 총순이익으로 내려왔다. 주석은 「별도재무제표인 경우에만」이라고 설명하지만 실제 분기는 재무 범위를 검사하지 않았다. `지배기업 소유주지분`이라는 이름으로 찾는 경로는 포괄손익계산서의 포괄손익 행과도 충돌할 수 있었다.

연결 총순이익 1,000, 비지배 순이익 200, 지배주주 EPS 10인 합성 입력에서 기존 함수는 100주를 냈다. 일치하는 분자의 결과는 80주다. 잘못된 근거를 받아 계산 자체는 정상 종료하는 결함이다. 실제 엘앤씨바이오 원문에는 지배주주 순이익 표준계정이 있어 이 잘못된 경로가 이번 최종 분모에 사용된 것은 아니다.

현재는 명시적으로 `OFS`인 별도재무에서만 총순이익을 허용하고, 연결에서는 지배주주 순이익 표준계정이 없으면 중단한다. 포괄손익과 이름이 같은 행도 대체하지 않는다. 실제 데이터를 섞어 임의로 주식 수를 만드는 대신 부족한 범위를 드러내는 수정이다.

**5. [P2] 정상 공시의 EPS 분할 표시를 지원하지 않았다.**

실제 첫 `refresh`는 「주당이익 또는 지배기업 순이익을 찾지 못했다」며 실패했다. 2026년 반기 공시는 계속영업 EPS와 중단영업 EPS를 별도 표준계정으로 제공했다. 예를 들어 희석 계속영업 EPS는 -1,059원, 중단영업 EPS는 명시적 0원이었다. 기존 함수는 합계 EPS 계정만 찾아 이 공시를 읽지 못했다.

동일 종류의 계속·중단 EPS가 **둘 다 공시된 경우에만** 더하도록 수정했다. 계속영업 EPS만 있는데 중단영업을 0으로 가정하거나 기본·희석 값을 섞는 경로는 거부한다. 원문에 직접 공시된 가중평균 기본주식 수 26,433,212주와 EPS 역산 26,438,908.97주는 EPS 반올림 때문에 일치하지 않는다. 이번 수정으로 정확한 발행주식 수를 복원했다고 주장하지 않는다.

**6. [P2] 컨센서스 실패와 미수집을 구분하지 않는다.**

여러 번 실행한 컨센서스 수집은 「요약 값을 읽지 못했다」로 실패했지만 packet은 `REGISTERED_NOT_COLLECTED`와 refresh 안내를 계속 제공했다. 데이터 부재인지 페이지 형식 변경인지 이번에는 확정하지 못했다. 이 상태를 단순히 수집 전으로 표시하면 다음 모델이 같은 재시도를 반복한다. 실패 사유·시점·재시도 가능 여부를 전달할 필요가 있으며, 이번 판단은 컨센서스를 지어내지 않고 직접 이익 시나리오를 사용했다.

**검증과 해석의 한계**

- Python 3.13 전체 테스트 **1,275개 통과**. EPS 분할·연결 범위·발행공시·기업행동 조사 요구·분할매수 산술 회귀를 포함한다.
- 실제 경로는 등록 → refresh 실패 → 원문 조사 및 수정 → refresh → score → PASS packet → 가정 계산 → validate → record → show까지 완료했다.
- 최종 기록: `CIO-73afac82ffe4e22da35a`, 컨텍스트 `CTX-1605e1f643fde47fe6fe`, 가정 계산 `ASM-9eca84bd1928e3e8dddf`. 원본·개인 조건은 Git에서 제외된 기존 저장 경로에 있다.
- 검증 통과는 EPS·PER·확률의 타당성을 보증하지 않는다. 이번 승리확률도 보정된 성과 통계가 아니다. 다만 이 일반적인 한계를 새로운 버그로 세지 않고, 이번에 실제로 재현한 경로를 위에 구분했다.
- 분할매수 본계약과 기업행동 자동 검증은 끝내지 않았으며 미해결 조사 요청으로 남겼다. 보완된 코드가 투자 판단을 대신하지 않는다.

## 사용자 검토 후 후속 수정

사용자 검토에 따라 주문 상태 관리 없이 제안의 금액·조건·가격 기준을 보존하는 최소
계약을 추가했다. 널리 쓰이는 방법과 관행적인 가정은 활용하되 모델이 적용 여부와
값을 선택하고, 프로그램이 투자 판단을 대신하지 않도록 정리했다. 아래는 위 발견
기록 이후의 상태다.

- `entry_plan`의 미래 예산을 현재 제안액과 합쳐 저장된 사용자 예산에 대조한다.
  `record`, `show`, 다음 packet이 같은 계획을 사용한다. 새 계획이 없는 중간 판단도
  최근 유효 계획의 참조를 지우지 않는다.
- 조건 확인 기록 이후의 가격 접촉을 평가하고, 미확인 조건이나 단위 불일치를 체결로
  가정하지 않는다. 실제 집행과 전체 전략 수익률은 미확인으로 둔다.
- DART 유·무상증자 서식의 주식수·배정비율·발행가·일정을 원문에서 추출하고 지문 및
  재추출 값으로 검사한다. 예정일이 지났다고 완료로 처리하거나 청약권 보유를 만들지 않는다.
- EPS 가정은 모델 전망 순이익·선택 분모·무상 전후 가격 단위의 산술에 연결한다.
  전망·PER·확률의 기본값이나 자동 매수 기준은 추가하지 않았다.
- 컨센서스 빈 칸과 일부 표의 부재가 유효한 실적 전망을 버리지 않게 했다. 실제 290650
  원문에서 전망을 복구했고, 네트워크·해석 실패·자료 없음·부분 성공을 나눠 전달한다.
- prompt 2.9는 관행적인 방법과 가정의 활용을 명시적으로 허용한다. 기존 근거·대체
  계산 계약에 적용 이유와 한계를 남기며, 별도의 승인 절차나 고정 투자 기준을 만들지 않는다.

지원 범위와 남는 자료 확인 책임은 [현재 계약](../advisory-plans.md)에 있다.
이 후속 수정은 이미 저장된 투자 판단이나 당시 가정을 새 분석으로 덮어쓰지 않는다.

후속 검증: 전체 테스트 1,294개 통과. 실제 290650 원문 → 새 PASS packet → 기존
모델 가정의 분모 연결 → 분할 예산 재계산을 확인했다. 기존 판단의 유효성도 유지됐다.
판단 바로 다음 거래일에 분할이 일어나는 경우에는 첫 사후 봉이 아니라 질문일의
보정계수를 쓰도록 수정하여, 주식 수 변화만으로 손실이 생기는 계산을 막았다.
