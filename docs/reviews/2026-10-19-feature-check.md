손절·추매 판단과 감시 알림까지 이어지지 않는다.

## 정상 동작 확인

- 감시 루프는 정상이다. 마지막 사이클에서 9종목을 시세 오류 없이 조회했다.
- 두산로보틱스와 펩트론은 마지막 사이클(15:50) 이후에 등록됐다. 다음 사이클에 포함될 것으로 보이나 확인하지 않았다.
- API 서버는 127.0.0.1에 바인딩돼 있다. 다만 CORS가 `*`로 열려 있다.
- `validation`(데이터 준비)과 `verdict`(투자 판단)의 역할 분리 계약은 테스트로 지켜지고 있다.

## Top 5 User Stories

1. **평단 누락 알림**
   - Done when: 보유수량 > 0 이고 평단이 비어 있는 종목이 화면에 표시된다.
   - Done when: 평단을 입력하면 알림이 사라지고 수익률이 보인다.
2. **손절 기준 확인**
   - Done when: 정책의 종목당 최대 손실(200만 원) 대비 현재 손실이 표시된다.
   - Done when: 손실이 한도를 넘으면 감시 이벤트가 생긴다.
3. **추매 판단**
   - Done when: 자문서가 안전마진, 평단 대비 위치, 비중 한도(종목 25%)를 함께 보여 준다.
   - Done when: 데이터가 부족하면 "판단 불가" 사유를 표시한다.
4. **판단과 감시 연결**
   - Done when: 저장된 판단의 손절가와 재질문가가 감시 대상에 들어간다.
   - Done when: 가격이 닿으면 알림이 오고 재질문 패킷이 준비된다.
5. **준비 상태 설명**
   - Done when: `prepare`가 BLOCKED일 때 어떤 데이터가 부족한지 종목별로 보인다.
   - Done when: 부족한 데이터를 채우는 명령이 함께 안내된다.

## 성공 지표

- **Primary**: 평단과 판단이 모두 있는 보유 종목 비율 (현재 0/12)
- **Secondary**: `prepare`가 PASS인 종목 수, 감시가 문턱을 가진 종목 수
- **Guardrail**: 0원이나 가짜 기본값으로 계산된 평가액이 0건일 것. "PC가 매수·매도를 판정한다"는 표현이 화면에 없을 것.

## 리스크와 열린 질문

**리스크**
- 평단은 직접 입력만 쓰기로 했으므로 입력 오류를 막을 장치가 없다.
- 정책 필드를 CIO 계약에 넣을지 대시보드 전용으로 분리할지에 따라 변경 범위가 달라진다.

**열린 질문**
- 정책 스키마 충돌은 어느 쪽을 바꿀 것인가? (CIO 계약에 필드 추가 / 대시보드 전용 파일로 분리)
- (결정됨) 평단 누락 알림은 대시보드 배지와 감시 이벤트 둘 다에 표시한다.
