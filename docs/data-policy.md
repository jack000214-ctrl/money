# 데이터 정책

## 범위

지원 범위는 한국·미국의 상장 주식과 ETF다. 자산별 차이는 하나의 거대한 프롬프트가
아니라 `config/assets.json`의 registry와 refresh plan으로 라우팅한다.

필수 registry 필드는 다음과 같다.

- 시장·거래소·기본통화: `KR`/`US`, `KRW`/`USD`
- 상품 유형: `STOCK` 또는 `ETF`
- 가격 심볼과 공시원
- 공시 프로필: 한국 `DART_KIFRS`, 미국 `SEC_DOMESTIC_US_GAAP`
- 섹터·산업과 `analysis_lens`
- 적용 가능한 `valuation_family` 후보
- 비교할 벤치마크
- ETF이면 전략, 기초자산, 파생 사용, 레버리지, 구성 출처, 분배 정책

등록 정보는 사실과 분석 경로를 고르는 메타데이터다. 모델의 verdict를 미리 정하지
않는다.

## 새 자산 등록

미국 주식 예시:

```bash
python3.13 -m cio register NVDA \
  --name NVIDIA \
  --market US \
  --exchange NASDAQ \
  --asset-type STOCK \
  --price-symbol NVDA \
  --sector-code TECH_SEMICONDUCTORS \
  --analysis-lens SEMICONDUCTOR_CYCLE \
  --valuation-family NORMALIZED_CYCLE DCF \
  --benchmark '^IXIC' \
  --benchmark XLK \
  --filing-source SEC_EDGAR
```

ETF는 `--asset-type ETF`와 함께 전략·기초자산·파생 여부·분배 정책을 등록한다.
등록 후 반드시 refresh plan을 확인해 실제로 필요한 수집기가 있는지 검토한다.

한국 상장 ETF 예시 (해외 종목을 담는 테마형):

```bash
python3.13 -m cio register 0053L0 \
  --name "TIGER 차이나휴머노이드로봇" \
  --market KR --exchange KOSPI --asset-type ETF \
  --price-symbol 0053L0.KS \
  --sector-code THEMATIC_CHINA_HUMANOID_ROBOTICS \
  --analysis-lens THEMATIC_EQUITY_ETF \
  --valuation-family ETF_LOOKTHROUGH \
  --benchmark 399001.SZ --benchmark '^HSI' --benchmark '^KS11' \
  --etf-strategy PASSIVE_THEMATIC --distribution-policy DIVIDEND_QUARTERLY \
  --issuer MIRAE_TIGER --isin KR70053L0005 \
  --currency-hedged no --total-fee-pct 0.49 \
  --optional-collector ETF_CONSTITUENTS
```

- `--issuer`·`--isin`이 있고 그 운용사 경로가 확인돼 있으면 구성종목을 자동으로
  받는다. 지금 확인된 경로는 `MIRAE_TIGER` 하나다. 없으면 구성종목은 수동이다.
- `--currency-hedged`는 모르면 생략한다. 생략은 "모름"이고 `no`와 다르다.
- 벤치마크는 **가격 이력이 있는 심볼**로 고른다. 야후가 이력을 한 행만 주는
  지수(`000300.SS`, `399006.SZ`)가 있고, 그런 심볼은 수집은 통과하지만 수익률이
  전부 null이다. packet이 `THIN_HISTORY`로 알리며 그때 바꾼다.
- 해외 지수를 벤치마크로 두면 통화가 다르다. 사후 평가의 `excess_pct`에 환율이
  그대로 들어가고 `_currency_warning`이 붙는다.

## 기본 수집 계획

`python3.13 -m cio refresh <asset_id>`는 쓰기 없이 현재 상태와 필요한 작업을 보여준다.
`--run`이 있어야 갱신하며, 신선한 산출물은 건너뛴다. `--force`는 신선도와 무관하게
다시 실행한다.

공통 필수 데이터:

- 대상 가격과 벤치마크 가격
- 시장 국면 계산에 필요한 가격
- 입력 가격·금액을 포함한 컨텍스트 기준시점

미국 자산에는 원·달러 환율과 VIX를 필수로, 미국 10년물 금리는 보조로 추가한다.
한국 시장은 KOSPI·KOSDAQ을 필수로 보고 VIX는 글로벌 보조 지표로만 쓴다.

주식:

- 한국: DART 재무 스냅샷과 가격·벤치마크 기반 중요 이벤트
- 미국: SEC EDGAR 재무 스냅샷과 최신 제출 문서 색인

현재 미국 주식 자동 재무 복원은 SEC 10-K/10-Q의 US-GAAP 국내 발행인만 지원한다.
20-F/6-K·IFRS 외국 발행인과 ADR은 미장 범위 밖이 아니라 **아직 자동 어댑터가 없는
경로**다. 이를 국내 발행인으로 잘못 등록해 PASS시키지 않으며, 별도 수집기를
추가하기 전에는 공식 숫자 판단을 만들지 않는다.

ETF:

- registry에 명시된 출처의 구성 스냅샷과 운용사 구조 정보
- 단일 기초자산형이면 기초자산 가격

ETF holdings는 필수 작업이다. 운용사 수집 경로가 확인된 ETF는
`collectors.kr_etf_holdings`가 운용사 원문에서 받고, 그 밖의 ETF는 수동이다.
수동일 때는 최신 운용사 원문을 우선 확인하되 2차 출처를 썼다면 registry와
컨텍스트에 그 등급을 드러낸다. `knowledge/etfs/<asset_id>/holdings-*.csv`로
저장하기 전에는 refresh가 `MANUAL_REQUIRED`를 반환하며, ID·중복·비중·기준일
계약을 통과해야 한다.

### ETF 구성종목을 받는 방법

```bash
python3.13 -m collectors.kr_etf_holdings 0053L0     # 운용사 원문 → holdings CSV
python3.13 -m collectors.etf_constituents 0053L0    # 종목별 가격·배수·환율
python3.13 -m calculators.etf_lookthrough 0053L0    # 가중 배수와 수익률 분해
```

`refresh --run`이 첫째를, `refresh --run --optional`이 둘째까지 돌린다(둘째는
`optional_collectors`에 `ETF_CONSTITUENTS`가 있을 때).

**구성종목 (`kr_etf_holdings`).** 받은 표가 운용사가 선언한 행수와 다르면
저장하지 않는다 — 기본 행수가 10이라 주소를 잘못 만들면 상위 10종목만 오고, 그
파일은 형식이 정상이라 전체처럼 읽힌다. 기준일은 운용사가 말한 날짜를 쓰며 못
읽으면 조회일로 대신하지 않고 멈춘다. 원화예금 같은 현금성 행은 구성종목에서
빼고 뺀 사실을 CSV 머리말과 `issuer.json`에 남긴다. 종목코드는 아는 표기만
바꾼다(`300124 C2 EQUITY` → `300124.SZ`). 모르는 표기는 원문 그대로 두고 시장을
비우며, 그 종목은 가격·배수를 받지 않는다. 기준가·총보수·환헤지 문구도 같은
페이지에서 읽어 `knowledge/etfs/<asset_id>/issuer.json`에 둔다. 환헤지는 운용사
문구 그대로 싣고 참·거짓으로 접지 않는다.

자동 수집본은 조회시각으로 신선도를 잰다. 기준일로 재면 긴 연휴 뒤에는 방금
받은 최신 구성도 낡은 것이 되어 packet이 멈춘다. 대신 기준일이 조회일보다 14일
넘게 뒤처지면 계약 위반이다 — 운용사가 갱신을 멈췄거나 다른 펀드를 받은 것이다.
손으로 적은 파일은 조회시각을 믿을 근거가 없어 예전처럼 기준일로 잰다.

**구성종목 재료 (`etf_constituents`).** 종목마다 세 가지를 받는다.

| 재료 | 출처 | 등급 |
|---|---|---|
| 창 수익률·12개월 고점 대비 낙폭 | Yahoo chart API (조정종가) | 구조화 시장 데이터 |
| forward·trailing PER, PS, PB, 순이익률 | stockanalysis.com 통계 페이지 | **2차 출처** |
| 종목 통화 → ETF 통화 환율 | Yahoo, 달러를 거친 교차환율 | 구조화 시장 데이터 |

배수는 2차 출처다. forward 추정의 기준연도와 표본 수를 그 페이지가 밝히지
않는다. 원문 페이지는 `cio snapshot`과 같은 저장소에 보존하고 받은 페이지의
제목이 그 종목의 것인지 확인한 뒤에만 값을 쓴다. 종목별 일봉은 저장하지 않는다
— 구성종목 수십 개의 일봉을 쌓으면 판단에 쓰이지 않는 행이 대부분이 된다.
환율을 교차환율 하나로 통일한 것은 야후의 직접 교차쌍(`CNYKRW=X` 등) 중 이력이
한 행뿐인 것이 있어서다.

확인한 거래소만 받는다 — 홍콩, 상하이, 선전, 도쿄, 한국, 미국. 그 밖의 종목은
`unresolved`에 남고 가중 계산에서 빠지며, 빠진 만큼 `*_weight_pct`가 줄어든다.

**들여다보기 산술 (`etf_lookthrough`).** packet의 `etf.lookthrough`에 실린다.

- 묶음 PER은 비중 가중 **조화평균**이다. 묶음의 PER은 시가총액 합÷이익 합이고
  비중이 시가총액 몫이므로 이익 몫은 비중÷PER이다. 산술평균을 쓰면 PER 200배짜리
  한 종목이 묶음 전체를 끌어올린다.
- forward PER이 없는 종목은 묶음 배수에 들어가지 않는다. 그 종목의 이익수익률은
  `순이익률÷PS`로 낸다. 순이익÷시가총액으로 내면 홍콩 상장 본토 기업처럼 실적
  통화와 시가총액 통화가 다른 종목에서 통화가 섞인다.
- 수익률 분해는 **현재 비중을 과거에 적용한 근사**다. 비중 변화·정기변경·보수·장
  마감 시차가 `unexplained_pp`에 남으며 0으로 맞추지 않는다.
- 창은 달력 일수(30·91·182·365일)다. 거래일 수로 재면 시장마다 휴장일이 달라
  같은 "3개월"이 종목마다 다른 기간이 된다. 그래서 `price.returns_pct`의 거래일
  창과 값이 다를 수 있다.

모델이 정한 문턱을 가격으로 옮기거나 이전 재료와 견줄 때는 직접 부른다.

```bash
python3.13 -m calculators.etf_lookthrough 0053L0 --at-forward-pe 22 20 --price 8245
python3.13 -m calculators.etf_lookthrough 0053L0 \
  --compare knowledge/etfs/0053L0/constituents-2026-10-09.json
```

`--compare`는 기준 재료의 비중·주가를 고정하고 종목별 내재 forward EPS(종가÷
forward PER)만 새 값으로 바꾼 묶음 PER을 낸다. "주가가 내려서 PER이 낮아진 것"과
"추정이익이 깎인 것"을 가르는 산술이다. 추정 기준연도가 넘어가면 이익이 늘어난
것처럼 보이므로 변화의 원인은 원문에서 확인한다.

**아직 없는 것.** 기준가·괴리율·추적오차 시계열, 기초지수 방법론(편입 기준·비중
상한·정기변경 일정), 기초시장 휴장 달력, 테마 매출 비중. packet의
`data_coverage`와 `research_requirements`가 이 공백을 말한다. TIGER 외 운용사의
구성종목 자동 수집도 없다.

### 해외 종목을 담은 한국 상장 ETF의 가격

`price.last_bar.is_settled_close`는 한국 세션만 본다. 한국 장은 15:30에 닫히고
중국 본토는 한국 시각 16:00, 홍콩은 17:00에 닫히며 휴장일도 다르다. 그래서 확정
종가라도 기초시장의 그날 마감과 한국 휴장일 동안의 움직임은 들어 있지 않다.
같은 이유로 그날의 `issuer_facts.price_vs_nav_pct`는 싸고 비쌈이 아니라 시차다.
`etf.lookthrough.constituent_price_as_of`와 ETF 가격 기준일을 대조한다.

포트폴리오 스냅샷은 보유 노출을 계산하는 보조 입력이다. 사용자가 종목·가격·금액을
직접 제시했으면 포트폴리오 파일이 없거나 오래됐다는 이유만으로 핵심 구매 질문을
막지 않는다.

`--optional`은 registry의 자산별 보조 작업을 포함한다. 현재 한국 수급·재고,
정상화 이익 등이 여기에 해당한다. 보조 작업의 실패는 필수 데이터 실패처럼
판정을 가장하지 않는다.

## 신선도와 실패

현재 refresh runtime의 기본 허용 나이는 다음과 같다.

| 데이터 | 최대 나이 |
|---|---:|
| 가격·벤치마크·미국 거시 가격 | 12시간 |
| 재무 스냅샷 | 720시간 |
| 미국 제출 문서 색인 | 24시간 |
| 한국 중요 이벤트 | 24시간 |
| ETF holdings | 168시간 (자동 수집본은 조회시각, 수동 파일은 기준일 기준) |
| ETF 구성종목 재료 | 168시간, 구성이 새로 수집되면 다시 |
| 계산된 시장 국면 | 24시간 |

산출물이 없거나 오래됐거나 의존 입력보다 먼저 만들어졌으면 `prepare`의
`validation.problems`에 드러난다. 오래된 값을 최신처럼 포장하지 않는다.

실행 신선도와 필수·보조 구분의 단일 권위는 `cio/refresh.py`다.

### 낡은 것과 틀린 것은 다르게 다룬다

refresh의 상태는 둘 다 `STALE`이지만 packet은 둘을 가른다.

| refresh가 본 것 | packet이 하는 일 |
|---|---|
| 기한이 지났다 (보조자료) | 값은 과거 관측으로 남기고 그 항목에 `freshness`·`_freshness_note`를 붙인다. `data_coverage`는 `STALE` |
| 계약을 어겼다 (`contract_error`) | 값과 근거 ID를 싣지 않고 `state: INVALID`와 사유만 남긴다 |
| 필수 입력이 어느 쪽이든 | `validation.problems`에 사유와 함께 올라가 BLOCKED. 재무가 계약을 어겼으면 숫자도 싣지 않는다 |

예전에는 refresh가 30일 된 수급을 STALE이라 하는데 packet은 같은 파일을 읽어
`AVAILABLE`로 실었다. 숫자를 읽는 자리와 가용성 표가 서로 다른 말을 했고, 모델이
보는 것은 packet 쪽이다. 수집기 둘이 한 줄을 이루는 항목(`flow_and_lending`,
`segment_revenue`)은 상태가 갈리면 `parts`에 각각을 적는다.

### 지금 받았다는 것과 지금의 값이라는 것

신선도는 회수시각으로 잰다. 그것만으로는 과거에 끝난 시계열을 오늘 받아도
신선하다. 가격 파일은 그래서 **마지막 봉의 날짜**도 본다 — 회수일보다 14일 넘게
앞서면(거래정지·상장폐지, 또는 응답이 과거 구간만 실었다) 현재 시세가 아니고,
회수일보다 뒤면 관측이 아니다. 수집기도 응답이 스스로 밝힌 종목이 요청과 다르면
저장하지 않고, 종가가 숫자가 아닌 응답은 통째로 버린다. 파일 이름이 정체성을
만들면 안 된다.

같은 이유로 2차 출처 CSV(수급·대차·재고)는 머리말의 종목코드가 요청 자산과
같아야 하고, 필수 열이 있어야 하며, 최근 20행에 값이 하나는 있어야 한다. 값이
없는 날은 합에서 빼고 `observed_sessions`로 몇 거래일이 실제로 관측됐는지 적는다.
**결측을 0으로 더하지 않는다** — "순매수 0주"는 관측이고 "값 없음"은 결측이다.

### 보완은 필수가 아니다

벤치마크 지수의 KRX 백필은 가격이 아니라 가격의 보완이다. 필수로 두면 KRX 키가
없는 설치에서는 Yahoo 가격과 재무가 멀쩡해도 표식 파일 하나 때문에 모든 한국
자산의 판단이 막힌다. 메우지 못한 구멍은 packet의 `session_gaps`가 말하고 그 날을
지나는 값은 싣지 않는다. 구멍이 있는지는 로컬 파일만으로 알므로, 메울 것이
없으면 키 없이도 "구멍 없음"이 기록된다.

## 컨센서스는 결론이 아니라 입력만 쓴다

`collectors.consensus`가 증권사 컨센서스와 목표주가 개정 이력을 시계열로 모은다
(FnGuide 재배포, `EXPLORATORY` 등급).

**목표주가는 밸류에이션 근거가 아니다.** 매도 리포트가 사실상 나오지 않아
목표가는 거의 항상 현재가 위에 있고 주가를 따라 개정된다. "목표가가 현재가보다
높다"는 거의 모든 커버 종목에서 항상 참이므로 정보가 아니다. 밸류에이션에는
`consensus_eps`(애널리스트의 이익 추정, 즉 **입력**)를 쓰고 멀티플은 모델이
직접 정한다.

수집기가 남기는 것은 셋이다.

| 항목 | 왜 |
|---|---|
| `consensus_eps` | 결론이 아닌 입력. 여기에 모델이 자기 멀티플을 곱한다 |
| 분산(30일·90일 두 창) | 15곳이 420,000~540,000으로 갈리면 평균은 합의가 아니다 |
| 개정 이력 | 상향·하향 **전환**은 관측 가능한 사건이다. 평균값 하나로는 안 보인다 |

분산을 두 창으로 내는 이유는 **시점 혼합**을 막기 위해서다. 주가가 저점이던
시절에 잡힌 목표가와 어제 잡힌 목표가는 같은 값이 아닌데, 출처의 3개월 평균은
둘을 섞는다. 두 창의 최대값이 다르면 `stale_targets_lift_the_mean`이 참이 되어
평균이 옛 목표가에 끌리고 있음을 드러낸다.

`peers`를 registry에 명시하면 동종도 **같은 수집기로** 모은다. EPS 기준·PER
계산·기준일이 전부 같아야 배수 비교가 성립하기 때문이다. 언론이 인용한 남의
배수는 기준연도도 주가시점도 알 수 없어 비교에 쓸 수 없다.

동종은 자기 registry 항목이 없다 — 비교 대상 자산의 `peers`에 선언될 뿐이다.
수집기의 ID 검사(`get_asset_or_declared_peer`)는 그 선언을 등록으로 인정한다.
2026-09-08에 등록 자산만 받는 검사가 들어가면서 동종 수집이 전부 실패했고,
packet은 5주 동안 낡은 동종 배수(중앙값 17.4배, 재수집 후 14.0배)를 실었다.

**PER 단독으로 동종을 비교하지 않는다.** 순현금 규모가 종목마다 다르면 PER 차이의
상당 부분이 자본구조 차이다. 2026-07-29 파마리서치는 PER 20.65배로 클래시스
16.3배 대비 27% 비싸 보였지만, EV/EBITDA는 11.9 vs 11.7로 사실상 같았다 —
순부채비율 -56.0% vs -26.6%의 차이였다. 그래서 컨텍스트는 두 배수를 함께 싣는다.

컨텍스트에는 제공처 목록을 싣지 않는다. 16곳의 표를 그대로 넣으면 패킷만
무거워지고 읽히지 않으므로, 위 세 가지를 숫자 열댓 개로 줄여 넘긴다.

요약·제공처별 의견·연도별 실적은 각각 읽는다. 빈 표 칸은 자리를 보존하고 null로
남기며, 목표주가나 기관수가 없다고 유효한 실적 전망까지 버리지 않는다. 구성요소별
`AVAILABLE`, `PARTIAL`, `NO_DATA`, `PARSE_ERROR`, `NETWORK_ERROR`를 구분한다.
실패한 시도는 `knowledge/collection_status/`에 따로 보존해 기존 성공 자료를 덮지 않고,
packet은 실패 사유와 과거 자료를 구분한다. 자료 없음과 연결·해석 실패를 같은
「미수집」으로 표시해 반복 수집을 유도하지 않는다.

제공처별 최신 보고일과 실적 전망 자체의 개정일은 다르다. `estimates_as_of`를
모르면 null이며 수집일을 대신 넣지 않는다. 목표주가 보고일이 없는 경우 `as_of`도
null이고 그 날짜의 개정 이력을 지어내지 않는다.

추정이 실적 공시를 반영했는가도 같은 구분을 따른다. 전망 갱신일을 알고 그 뒤에
실적 공시가 나왔으면 `stale_across_event`(반영하지 않았다)를 붙인다. 갱신일을
모르면 최신 목표가 보고일 이후의 실적 공시를 `unverified_across_event`로 싣는다 —
반영했다고도 안 했다고도 읽지 않는다. 예전에는 목표가 보고일을 전망일로 바꿔
부르며 "반영하지 않았다"고 단정했다.

## 가격 시계열의 함정

가격 수집은 실패하지 않고도 틀린 값을 준다. 전부 계약으로 막는다.

**장중 미확정 봉.** 개장 중에 수집하면 진행 중인 봉이 확정 일봉과 같은 형태로
마지막 줄에 들어간다. `price-series/2.1.0`은 `# last_bar <날짜> / session
<SETTLED|UNSETTLED|UNKNOWN>` 줄을 요구하고, 이 줄이 없으면 계약 위반이다.
컨텍스트 패킷은 `price.last_bar`로 모델에게 확정 여부를 알리고,
`collectors.kr_events`는 미확정 봉을 급변 판정과 거래량 배수에서 제외한다.

**벤치마크 거래일 구멍.** Yahoo는 거래일을 통째로 빠뜨리고도 정상 응답을 준다.
그러면 일별 상대변동이 이틀치를 하루로 합쳐 계산돼 초과수익 부호까지 뒤집힌다.
`collectors.kr_events`는 종목과 벤치마크가 **같은 직전 거래일**을 쓸 때만
상대변동을 내고, 어긋난 날은 `benchmark.calendar_gaps`에 남긴 뒤 값을 `null`로
둔다. 근사하지 않는다. 복구는 거래소 원문으로 한다.

**조용히 굵어지는 봉.** Yahoo는 `interval=1d`로 요청해도 `range`가 크면 봉을
스스로 굵게 만든다 — `range=max`는 `dataGranularity=1mo`로 월봉을 돌려주면서
HTTP 200이다. 그대로 저장하면 2,447행짜리 일봉 파일이 320행짜리 월봉으로
덮이는데, 한 행이 하루라는 전제는 헤더가 아니라 **코드에만** 있어서 그 뒤의
변동성·이동평균·거래량 배수·급변 판정이 전부 월봉 위에서 조용히 계산된다.
실제로 그랬다. `collectors.price`는 저장 **전에** 봉 굵기를 확인하고
(`meta.dataGranularity`, 없으면 행 간격 중앙값) 일봉이 아니면 파일을 건드리지
않은 채 멈춘다. 쓰기를 막는 것만으로는 사고 이전에 저장된 파일이 남으므로
`cio refresh`도 가격 파일의 행 간격을 대조해 일봉이 아니면 계약 위반으로 낸다.
10년 이상이 필요하면 `--range 10y`가 상한이다.

봉 굵기를 판정할 수 없을 때(행이 한 줄뿐, 갓 상장한 종목)는 막지 않는다.
**모르는 것과 위반은 다르다** — 확인된 위반만 막는다.

**응답에서 빠진 날짜와 잠정 마지막 봉.** 재수집은 저장된 봉을 지우지 않는다.
응답에 없는 날짜는 "그날이 없었다"가 아니라 "이번에 안 실었다"이고, Yahoo는
수집 범위 **안의** 하루를 빼고도 정상 응답을 준다. 2026-10-13에는 파마리서치와
코스닥 지수의 10-12가 그렇게 사라졌다. 예외는 하나다 — **저장된 마지막 봉은
잠정값이다.** 다음 수집이 다시 실어 준 적이 없는 유일한 봉이라, 장중 수집분이면
종가가 아니고 `SETTLED`로 적혔어도 장 마감 직후의 값은 뒤에 바뀐다(같은 날
코스피 10-12가 6,399.43 → 6,384.24). 그래서 마지막 봉은

- 분할 판정의 대조에서 뺀다. 그 하루의 정정을 액면분할로 읽어 가장 오래된
  40거래일을 버린 적이 있다. 진짜 분할은 그 이전의 모든 봉을 바꾸므로 하루를
  빼도 드러난다
- 응답에 없으면 값을 보존하지 않고 날짜만 머리말의 `# missing_sessions`에
  남긴다. 장중 값을 종가로 굳히는 것보다 비어 있다고 말하는 쪽이 낫다

**한국 시계열의 구멍은 거래소 원문으로 메운다.** 지수와 종목 모두다.

```bash
python3.13 -m collectors.krx backfill KOSPI
python3.13 -m collectors.krx backfill-stock 214450           # 접미사로 시장을 정한다
python3.13 -m collectors.krx backfill-stock 0053L0 --market ETF
```

거래일 달력은 로컬의 **한국 시계열 전체의 합집합**이다 — 종목 파일, 코스피·코스닥
지수 파일, 그리고 `# missing_sessions`에 남은 날짜. 유가증권시장과 코스닥시장은
휴장일이 같아서 달력이 하나이고, 한 파일은 자기 구멍을 볼 수 없으므로 다른 파일에
그 날짜가 있어야 보인다(10-12를 가진 것은 코스피 지수뿐이었다). 모든 파일이 같은
날을 함께 잃고 기록도 없으면 로컬에서는 알 수 없다.

원문은 그날의 실제 호가라서 저장된 시계열의 기준(오늘 기준 분할 반영, 배당이 든
조정종가)으로 옮겨야 한다. 그 기준은 **앞뒤 봉이 같은 값을 말할 때만** 입힌다.
분할일·배당락일이 빈 날의 앞인지 뒤인지 알 수 없으면 메우지 않고 사유를
`unfilled_reasons`에 남긴다. 종목 거래량은 Yahoo와 단위가 같아 채우고, 지수
거래량은 단위가 달라 비운다. 메운 날짜는 머리말의 `# backfilled`에 남고 다음
재수집에서도 봉과 함께 보존된다.

`refresh`가 가격 수집 뒤에 이 작업들을 자동으로 돌린다. 종목·지수 백필 모두
**필수가 아니다** — 거래소 API가 막히거나 키가 없어도 판단을 세우지 않으며
([보완은 필수가 아니다](#보완은-필수가-아니다)), ETF 서비스는 활용신청이
따로다. 백필 기록(`knowledge/prices/_backfill/*.json`)은 메웠다고 적은 거래일이
실제로 파일에 있는지 계약 검사에서 대조한다.

메우지 못한 구멍은 packet이 말한다. `price.session_gaps`는 같은 거래소 달력의
지수와 대조해 최근 30세션 안에서 이 시계열에 없는 거래일을 싣고(없으면 빈 목록,
대조할 달력이 없는 시장이면 필드 자체가 없다), 그 구멍에 걸친
`settled_session_returns` 창은 내지 않는다 — 수익률 숫자는 맞아도 몇 세션의
수익률인지가 틀리기 때문이다. `validation.optional_gaps`에 `SESSION_GAP`으로도
남는다. 판단을 막지는 않는다. 해외 지수와 변동성 지수는 휴장일이 달라 대조에
쓰지 않는다.

## 분기 환율표

원화로 보고하는 수출 회사의 매출은 분기 **평균** 환율로, 외화 화폐성 자산은
**기말** 환율로 환산된다. 한국 주식의 packet은 달러/원을 그 회사의 결산 분기에
맞춘 표를 싣는다(`structured_optional.fx_usdkrw`).

| 필드 | 뜻 |
|---|---|
| `quarters[].average` / `period_end` | 그 분기 일봉 종가의 단순평균과 마지막 값 |
| `average_qoq_pct` / `period_end_qoq_pct` | 표에서 바로 앞 줄이 실제 직전 분기일 때만 |
| `average_yoy_pct` | 전년 동기 평균 대비 |
| `reported` | `false`면 끝났지만 실적이 아직 나오지 않은 분기 |
| `latest_vs_last_reported_quarter` | 최근 환율이 마지막 발표 분기의 평균·기말 대비 어디인가 |
| `export_share` | 품목군을 내수·수출로 나눠 공시하는 회사만. 아니면 `null` |

분기 경계는 `fundamentals.earnings_bridge`의 기말 날짜를 쓴다. 봉이 32개 미만인
분기와 아직 끝나지 않은 분기는 근사하지 않고 뺀다. 산술은
`calculators/fx_periods.py`에 있고 `tests/test_fx_periods.py`가 고정한다.

**이 표는 환율이 실적을 얼마나 움직이는지 말하지 않는다.** 통화 구성·헤지·
이익 전이율은 회사마다 다르고 그것을 정하는 것은 모델이다. 회사가 공시한 외화
화폐성 자산과 10% 민감도는 수집기로 만들지 않았다 — 주석 표의 모양이 회사마다
달라 파서가 회사 수만큼 필요해지는 자리이고, 원문은 이미 로컬에 있어서
`cio search <asset_id> 환위험`으로 읽힌다. 값은 Yahoo 현물 종가라 회사가 쓰는
매매기준율과 다르며, 엔·위안·유로는 싣지 않는다.

이 표가 생긴 이유: 2026-10-06 판단은 수출 비중 47% 회사에서 환율을 다루지
않았다. packet에 환율이 없었고, 일주일 뒤 그 누락을 고치자 base EPS가 5.6%,
같은 가격의 기대수익이 17.99% → 12.18%로 움직였다.

## 공매도 잔고를 받을 수 없는 이유

`collectors.kr_lending`이 종목별 **대차잔고**를 data.go.kr
금융위원회_주식대차거래정보(15124865)에서 받는다. 원천이 한국예탁결제원 집계인
정부 공식 개방데이터이므로 네이버 재배포와 달리 `MARKET_DATA`로 싣는다.
`.env`의 `DATA_GO_KR_API_KEY`가 필요하다. **가격보다 한 세션 늦다** — 2026-08-03
장 마감 뒤에도 대차잔고의 최신 행은 07-31이었다. 급변 당일의 대차는 다음날에야
보이므로, 오늘 움직임을 대차로 설명하려 들면 안 된다.

**이 API는 모르는 파라미터를 조용히 무시한다.** 종목 필터 이름을 틀리면 오류나 빈
결과가 아니라 **전 종목 52,000행**이 돌아온다. 그대로 저장하면 다른 종목의 대차잔고를
이 종목 것으로 읽는다. 실제로 후보 4개 중 3개(`likeStckItmsCd`·`itmsCd`·`likeItmsCd`)가
그렇게 동작했고 맞는 이름은 `stckItmsCd` 하나였다. 그래서 수집기의 `verify_rows`가
응답에 다른 종목이 한 줄이라도 섞이면 저장하지 않고 멈춘다. **다른 금융위 API를 붙일
때도 같은 검사를 먼저 넣는다** — 이 계열 API의 기본 성질이지 이 서비스만의 버그가 아니다.

data.go.kr 인증키는 Encoding·Decoding 두 벌로 나온다. Encoding 쪽을 그대로 쓰면 `%`가
`%25`로 다시 인코딩돼 "등록되지 않은 서비스키"가 된다. `load_key`가 어느 쪽이든 풀어서
한 번만 인코딩한다.

**공매도 잔고는 못 받는다.** 판단 두 건이 `positioning.unobservable`에 적어 둔
항목을 2026-08-03에 전부 확인한 결과이며, 여기 적는 이유는 **다음 세션이 같은
탐색을 반복하지 않게 하기 위해서다.**

| 경로 | 결과 |
|---|---|
| KRX Open API (`data-dbg.krx.co.kr`) | 공매도·대차 서비스 없음. 후보 8개 전부 404 |
| `data.krx.co.kr` 정보데이터시스템 | `getJsonData.cmd` → `LOGOUT`. 로그인 전용으로 바뀜 |
| `short.krx.co.kr` 공매도종합포털 | 같은 로그인 벽 |
| 네이버 금융 | `short_sale.naver` 404. 종목 페이지에서 공매도 항목 삭제됨 |
| 금투협 freeSIS 직접 | 웹방화벽 차단 |
| data.go.kr | 종목별 공매도 잔고 API 없음 |

신용융자도 종목 단위로는 없다. 금융위원회_금융투자협회종합통계정보(15094809)의
`getGrantingOfCreditBalanceInfo`는 **시장 전체 신용공여 잔고 추이**이지 종목별이
아니다. 개별 종목 판단을 바꾸지 못하므로 붙이지 않았다.

**이 표가 낡을 수 있다.** KRX가 로그인 정책을 되돌리면 다시 열린다. 다만 그때까지는
`kr_lending._unobservable`이 packet에 실려 나가고, 모델은 없는 것을 찾지 않는다.

## 출처 우선순위

1. 거래소·규제기관
2. 발행사·운용사
3. 구조화 시장 데이터
4. 신뢰 가능한 뉴스
5. 기타 탐색 자료

DART와 SEC EDGAR의 원문·구조화 재무가 기업 사실의 우선 근거다. 뉴스는 새로운
질문과 사건을 찾는 데 쓸 수 있지만 핵심 숫자의 단독 근거로 승격하지 않는다.
ETF 구성과 분배 구조는 운용사 원문을 우선한다.

DART·EDGAR 원문은 payload SHA-256으로 내용 주소화한다. 같은 응답을 여러 번 받아도
원문 객체는 하나만 남기고, 회수시각 차이만 있는 개발 중복본은 지식 자산으로
증식시키지 않는다.

### 공시 색인

`knowledge/filings/<asset_id>.json`은 모델이 원문으로 들어가는 진입점이다.
미국은 SEC submissions, 한국은 DART `list.json`이며 둘 다 같은 `filing-index/1.0.0`
행 모양을 쓴다. 색인은 언제나 저장된 원문에서 다시 계산할 수 있어야 하고,
`refresh`의 계약 검사가 매번 재현해 대조한다 — 손으로 고친 색인은 STALE이 된다.

DART는 공시유형(`pblntf_ty`)을 지정하지 않으면 임원·주요주주 소유상황보고서 같은
지분공시가 목록을 덮는다. 삼성전자는 그것만 하루 십수 건이라 정기보고서와
잠정실적이 첫 페이지에서 밀려난다. 그래서 정기공시·주요사항보고·발행공시·거래소공시·
외부감사관련만 따로 받아 합친다.

발행공시(C)의 증권신고서·투자설명서에는 증자 조건과 사업별 위험이 있다.
이 갈래가 빠지면 원문을 받아도 종목 색인과 연결되지 않아 `cio search`가
찾지 못한다. 정정본은 변경 부분만 담을 수 있으므로 최신 투자설명서와 원래
신고서도 확인한다. [실제 재현과 보완](reviews/2026-09-08-290650-adversarial.md).

색인은 최신 사건을 보는 창이라 한국 60건·미국 50건에서 잘린다. **원문과 자산의
연결은 그 창보다 오래 산다.** 색인에 한 번이라도 실린 행은
`data/raw/filing-links/<asset_id>.json`에 계속 쌓이고(수집기가 색인을 덮어쓰기
전에, 그리고 문서 목록을 읽을 때), 창 밖으로 밀린 공시의 원문도 `cio docs`·
`cio search`에 그대로 남는다. 오래된 미수집 공시를 "아직 안 받음"으로 다시
늘어놓지는 않는다.

DART EPS가 계속·중단영업으로 나뉘면 같은 기본/희석 종류의 두 값이 모두 있을
때만 더한다. 연결재무의 분자는 지배주주 순이익이며, 총순이익 대체는 명시적인
별도재무에만 허용한다. EPS 역산 주식수는 보고기간의 분모이고 반올림 오차도 있어
현재 발행주식수나 예정 증자 후 주식수로 사용하지 않는다.

`form`은 DART 보고서 이름으로 나눈 갈래이지 법정 서식 코드가 아니다. 분류에
실패하면 `OTHER`로 두고 원래 이름을 `description`에 그대로 남긴다 — 여기서 뜻을
지어내지 않는다.

### 원문 검색

보존한 원문은 통째로 모델에 넣지 않는다. 삼성전자 사업보고서는 원문 897만 자,
태그를 걷어내도 103만 자다. 컨텍스트 예산의 30배가 넘는다.

`cio search`가 태그를 걷어낸 사본에서 물어본 자리만 잘라 준다. 사본은
`data/raw/text/<지문>.txt`에 지문별로 한 번만 만든다 — 원문이 내용 주소라 절대
바뀌지 않으므로 사본도 다시 만들 필요가 없다. 원문 자체는 손대지 않는다.

태그를 걷어낼 때 표의 행과 칸 경계는 남긴다(`|`와 줄바꿈). 재무 표를 공백
하나로 이어 붙이면 어느 숫자가 어느 항목인지 알 수 없게 되기 때문이다. DART
정기보고서는 숫자 칸을 `TD`가 아니라 `TE`로, 단위 칸을 `TU`로 적으므로 넷 모두
칸 경계다. 추출 규칙을 고치면 `TEXT_EXTRACT_VERSION`을 올려 사본을 다시 만든다.

검색 결과는 발췌 총량과 건수에 상한이 있다. 원문을 넣지 않으려고 만든 도구가
발췌로 예산을 먹으면 뜻이 없다.

**검색어의 괄호에 주의한다.** `연결재무제표기준영업(잠정)실적`은 정규식으로도
유효하지만 `(잠정)`을 그룹으로 읽어 실제로는 다른 것을 찾는다. 오류가 나지
않으므로 조용히 0건이 되고, 모델은 원문에 없다고 결론짓는다. 한국 공시 이름은
괄호투성이라 이것이 가장 흔한 함정이다. 그래서 0건이면 문자 그대로 다시 찾고
`treated_as_literal`로 그 사실을 알린다.

검색 결과에는 **아직 받지 않은 공시** 목록이 함께 나온다. 색인에는 있으나 원문을
받지 않은 문서를 알려주지 않으면, 모델은 "검색했는데 없다"와 "받지 않아서 없다"를
구분할 수 없다.

### 모델이 조사한 원문

`cio snapshot`이 저장하는 것은 응답 바이트 그대로다. 광고·마크업을 걷어내지
않는다. 정제는 페이지가 바뀔 때마다 깨지고 그 유지보수가 사람에게 돌아오지만,
받은 그대로의 바이트는 깨지지 않는다. 무엇이 본문인지는 그 파일을 읽는 모델이
판단한다.

현재 이 경로는 텍스트 응답만 지원한다. `body_encoding`으로 엄격히 디코딩하고
재인코딩한 바이트가 원문과 같음을 확인한다. PDF·바이너리나 손실 없이 읽을 수 없는
본문은 저장·색인 전에 거부한다. PDF를 UTF-8 대체문자로 바꾼 결과를 원문이라고
보존하거나 검색 근거로 제공하지 않는다.

응답에 프레임만 있고 본문이 없으면 `shell_page_warning`을 붙인다. DART 뷰어
주소(`dsaf001/main.do`)가 대표적이다 — 주소는 공시를 가리키지만 내용은 iframe으로
따로 불러오므로, 그대로 저장하면 "원문을 보존했다"는 기록만 남고 내용은 없는
가장 나쁜 근거가 된다. 한국 공시 원문은 접수번호로 받는다
(`collectors.dart document`).

### 잠정실적 원문은 refresh가 받는다

색인은 제목과 접수번호만 담고, 원문은 원래 **모델이 직접** 받는 설계였다. 그
설계의 구멍이 2026-08-07에 드러났다 — 판단이 답하지 못한 질문(영업이익률 하락이
믹스인가 판가인가)의 근거인 품목군별 매출은 잠정실적 공시 본문에 있었고 그 공시는
그날 이미 색인에 접수번호까지 실려 있었는데, 판단은 원문 수집을 사용자 대기열로
넘겼다. **모델이 안 받으면 아무도 안 받는다.** 색인에 있는데 안 받아서 못 본 것은
데이터가 없는 것이 아니다.

그래서 `filing_documents:<asset_id>` 작업이 색인의 잠정실적 공정공시 중 원문이
없는 것을 받는다(`collectors.dart documents`). 받는 대상은 `PROVISIONAL_RESULT`
**하나뿐이다.**

- 짧다 — 2,285자다. 정기보고서는 100만 자라 이 배선이 감당할 문서가 아니고,
  필요한 자리만 `cio search`로 읽는 것이 이 저장소의 방식이다
- 드물다 — 분기당 한 건이라 상한(8건) 안에서 1년치가 들어온다
- 그리고 **여기에만 있다** — 파마리서치의 품목군별 매출은 정기보고서에 없다.
  `collectors.kr_segments`를 돌려도 "사업부문별 요약 표를 특정하지 못했다"가 나온다

이미 받은 원문은 다시 받지 않으며(`stored_filing_keys`), 최신부터 받는다 —
상한에 걸릴 때 이번 분기 실적이 먼저 남아야 하기 때문이다. 색인이 갱신되면 함께
돈다(`dependencies`). `required=False`인 것은 의도다. 원문 하나를 못 받았다고
packet을 BLOCKED로 만들면 있으면 좋은 입력 때문에 판단 자체가 멈춘다.

이 배선의 첫 실행이 무엇을 했는지가 그 값어치다 — 아무도 요청하지 않은 3Q25·4Q25
잠정공시를 받아 왔고, 품목군 시계열이 3분기에서 5분기로 늘면서 **그 배선을 만들게
한 판단의 논지가 반증됐다.** 표본을 3개에서 5개로 늘리자 믹스 회귀의 R²가
0.82에서 0.11로 무너졌다.

### 품목군별 매출은 그 원문에서 시계열로 만든다

원문을 받아도 숫자는 본문 문장 안에 있어서, 판단마다 모델이 서너 건을 손으로 다시
읽었다. `KR_PRODUCT_SALES`(`collectors.kr_product_sales`)가 로컬 원문만 읽어
`knowledge/product_sales/<asset_id>.json`을 만들고, packet은
`structured_optional.kr_product_sales`로 최근 5분기 표와 최신 분기의 비중·전분기·
전년동기 변화율을 싣는다. 네트워크를 타지 않으며 `filing_documents`가 새 원문을
받으면 다시 돈다.

- **합을 대조한다.** 여덟 줄의 합을 같은 공시의 매출액과 맞춘다. 4분기는 '매출액
  또는 손익구조 변동' 연간 공시라 분기 매출 칸이 없으므로 연간 매출에서 같은 해
  3분기 공시의 누계를 뺀 값과 맞춘다. 허용 차이는 반올림 5백만원이며 넘으면
  `MISMATCH`로 남기고 변화율 계산에서 뺀다
- **기간이 어긋나면 싣지 않는다.** 원문 표기(26.2분기)가 공시의 실적기간과 다르면
  `PERIOD_CONFLICT`다. 단위가 백만원이 아니면 환산하지 않고 거부한다
- **회사는 공시 색인으로 맞춘다.** 색인은 1년 창이라 전년동기 원문이 빠져 나가는데
  바로 그때 전년동기 대비가 필요하다. 그래서 색인 밖 원문은 DART 제목의 회사명
  (첫 '/' 앞)이 등록명과 정확히 같을 때만 받고(`matched_by`), 한 번 만든 분기는
  다음 실행에서도 남긴다(`retained_from_previous`)
- **판정하지 않는다.** 변화율·비중은 산술이며 둔화·정체 같은 말은 만들지 않는다

### 재무의 신선도

수집시각이 아니라 결산 캘린더로 잰다. 3월 말 재무를 7월에 받아도 파일은
"방금 받은 것"이지 "최신 실적"이 아니다. `fundamentals.reporting_lag`이 공시
색인을 보고 로컬 기준일 이후의 정기보고서와 잠정실적 공시를 세며, 새 정기보고서가
이미 나왔으면 `validation`을 BLOCKED로 만든다.

공시는 **이미 끝난 기간만** 보고할 수 있다. 그래서 로컬 기준일 다음 분기말
전에 나온 실적 공시는 로컬이 이미 담은 분기를 말하는 것이라 세지 않는다 —
3월 말 재무에 5월 초 1분기 잠정실적을 미반영으로 세면 없는 공백이 매번 켜지고,
늘 켜져 있는 경고는 아무도 읽지 않는다.

미반영 공시가 있는데 **그 원문마저 로컬에 없으면** BLOCKED다. 색인에 제목이
있다는 것은 근거가 있다는 뜻이 아니며, 그 상태에서는 모델이 최신 실적을 확인할
경로가 packet 안에 하나도 없다. 원문이 로컬에 있으면 경고로 남고, 그 경고는
`earnings_bridge` 옆에 붙어 숫자를 읽는 자리에서 보인다.

이 판정은 조용히 통과하면 안 되는 자리라 네 가지를 지킨다.

- **줄이기 전의 색인 전체로 판정한다.** packet의 공시 요약은 정기보고서 4건·
  사건 8건에서 잘린다. 잘린 목록으로 판정하면 실적 공시 뒤에 다른 공시가 8건
  쌓였을 때 미반영 실적을 놓친다.
- **8-K는 Item 번호로 읽는다.** Item 2.02(실적)만 실적 공시다. 임원 교체(5.02)를
  최신 실적으로 세지 않고, 실적을 정정한 8-K/A는 뺀 적이 있어 포함한다. Item
  정보가 없는 옛 색인 행은 실적이 아니라고 단정하지 않는다.
- **확인하지 못한 것은 통과가 아니다.** 보존 원문 목록을 읽지 못하면 BLOCKED다.
- **본체만으로는 원문이 아니다.** 실적 8-K의 본체는 대개 "실적 자료는 Exhibit
  99.1"이라는 한 문단이다. 본체가 Exhibit 99를 가리키는데 같은 제출 폴더의 다른
  문서를 하나도 받지 않았으면 BLOCKED이고, 받을 첨부의 URL을 알려 준다.

### 재무 스냅샷은 원문에서 다시 나와야 한다

재무 스냅샷의 계약 검사는 내부 항등식(분기 합 = TTM, 차입 − 현금 = 순부채)과
내용 지문만이 아니다. **수집기의 도출 함수를 봉인된 원문에 다시 돌려 값을
대조한다** (`collectors.dart.replay_fundamentals`, `collectors.edgar.
replay_fundamentals`). 지문은 파일이 보존됐다는 증거이지 그 안의 숫자가 원문과
같다는 증거가 아니다 — 원문 OCF 40을 스냅샷에서 일관되게 400으로 바꾸면 항등식도
지문도 통과했다.

수집과 검사가 같은 함수(`derive_fundamentals`, `derive_us_fundamentals`)를 쓰므로
**추출 규칙을 고치면 옛 규칙으로 만든 스냅샷이 스스로 STALE이 된다.** 재수집이
답이며, 그 전까지 packet은 그 재무의 숫자를 싣지 않는다. 제출일(`filed`)만 다른
것은 차이로 치지 않는다 — 같은 분기 값이 이듬해 비교표에 다시 실릴 때마다 모든
스냅샷이 낡았다고 하게 된다.

### 총차입과 단기투자 — 찾은 줄의 합이지 전부라는 보증이 아니다

순부채 = 총차입 − 현금 − 단기투자다. 양쪽 모두 계정 목록에 걸린 줄만 더하므로,
목록에 없는 계정을 쓰는 회사에서는 조용히 틀린다. 실제로 그랬다.

| 자산 (기준일) | 빠져 있던 것 | 순부채 |
|---|---|---:|
| SK하이닉스 (2026-03-31) | 차입금 19.3조 (`CurrentBorrowingsAndCurrentPortionOfNoncurrentBorrowings`·`LongtermBorrowings`), 단기투자자산 14.9조 (`CurrentInvestments`) | −36.87조 → −32.50조 |
| 파마리서치 (2026-06-30) | 전환상환우선주부채 2,073억, 유동성금융자산 3,753억 (`OtherCurrentFinancialAssets`) | −2,066억 → −3,746억 |

두 누락은 방향이 반대라 서로를 가렸다. **한쪽만 고치면 순부채가 더 틀린다.**
파마리서치의 총차입 분류(전환상환우선주부채 + 전환사채 + 차입금 = 2,137억)는
회사의 자본관리 주석과 원 단위까지 같다.

그래서 두 가지를 한다.

1. 분류를 넓힌다. 총차입에 교환사채(`CONVERTIBLE`)와 부채로 분류된 전환상환우선주
   (`REDEEMABLE_PREFERRED`)를 넣고, 단기투자는 표준코드와 계정명(`유동성금융자산`,
   `단기투자자산`, 측정 범주가 붙은 변형)을 함께 본다. 분류별 합은
   `debt_by_category`, 센 계정은 `debt_detail`·`short_term_investments_detail`에
   있어 모델이 덜어내고 다시 셀 수 있다.
2. **분류하지 못한 후보를 값과 함께 남긴다.** 차입처럼 보이는데 목록에 없는 행은
   `debt_unclassified`(총차입은 하한), 현금성일 수 있는데 세지 않은 유동 금융자산
   (`기타금융자산` — 대여금·보증금이 섞인다)은
   `short_term_investments_unclassified`로 packet의 재무 옆에 실린다. 후보가
   있으면 `debt_basis`는 `MATCHED_LINE_ITEMS`가 아니라 `UNCLASSIFIED_CANDIDATES`다.

미국(us-gaap)은 문제가 다르다. 태그 정의에 포함관계가 있는데 회사가 정의대로
쓰지 않는 일이 흔하다 — `LongTermDebt`는 정의상 유동분을 포함한 총액이지만
비유동 줄에 붙이는 회사가 많다. 값만으로 가를 수 없는 조합은 **더하고**(덜 세면
회사가 싸 보인다) 겹칠 수 있는 금액을 `debt_overlap_candidates`로 남긴다. 값으로
가를 수 있는 것은 가른다: 단기차입금과 장기차입금 유동분은 둘 다 세고(`DebtCurrent`
총계가 있으면 그것 하나만), 금융리스는 같은 만기 쪽 차입이 품고 있을 때만 뺀다.

**미국 쪽에는 "분류하지 못한 차입 후보" 그물이 아직 없다.** 수집기가 태그를
하나씩 지정해 받으므로 목록 밖의 태그(`SeniorNotes`, `LongTermLineOfCredit` 등)는
보이지 않는다. companyfacts 한 번으로 회사의 전 태그를 받는 구조로 바꿔야 가능하며
(같은 변경이 요청 수도 줄인다), 그때까지 미국 종목의 총차입이 결론을 좌우하면
10-Q 재무상태표에서 직접 대조한다.

### 없는 것은 없다고 말한다

수집기가 못 찾은 항목을 그냥 비워 두면 packet에서는 **관측된 0**과 구분되지
않는다. IBM 재무 스냅샷은 영업이익이 통째로 비어 있는 채 계약을 통과했다 —
항등식이 OCF·capex·FCF·순부채만 봤기 때문이다. 지금은 손익계산서의 각 줄이
값을 갖거나 `absent_reason`을 가져야 한다(IBM은 `us-gaap:OperatingIncomeLoss`를
공시하지 않는다). PC는 없는 값을 근사하지 않는다.

같은 이유로 packet은 `data_coverage`로 입력별 가용성을 싣는다.

| state | 뜻 | 푸는 방법 |
|---|---|---|
| `AVAILABLE` | 값이 실렸다 | — |
| `STALE` | 값은 실렸지만 refresh 기한이 지난 과거 관측이다 | `cio refresh <id> --run --optional` |
| `PARTIAL` | 일부만 관측됐거나, 한 줄을 이루는 자료의 상태가 갈린다(`parts`) | 해당 항목의 사유를 본다 |
| `REGISTERED_NOT_COLLECTED` | 등록했는데 산출물이 없거나 계약 검사에 실패했다 | `cio refresh <id> --run --optional` |
| `NOT_REGISTERED` | 이 자산에 등록하지 않았다 | `config/assets.json`에 등록 |
| `NO_COLLECTOR_FOR_MARKET` | 이 시장에 수집기가 없다 | 만들거나, 모델이 직접 조사 |

미국 종목은 오랫동안 `optional_collectors`가 전부 비어 있었고 그 사실이 packet
어디에도 없었다. 특히 `NORMALIZED_EARNINGS`가 빠져 있어서 사이클 위치를 볼
수단 없이 단일 TTM으로만 판단됐다 — 한국 종목에서는 그 입력이 두 판단의 결론을
뒤집었다. 사이클은 시장의 성질이 아니라 회사의 성질이므로 계산기에 EDGAR 경로를
붙였고(`calculators.normalized_earnings`가 registry의 `filing_source`로 갈린다),
컨센서스·부문·수급처럼 정말로 미국 경로가 없는 것은 `NO_COLLECTOR_FOR_MARKET`로
그렇게 말한다.

## 결정론적 계산

### EPC 연결 도급공사계약 주석

`KR_EPC`는 한국 EPC 주식에 선택적으로 등록하는 수집기다. `collectors.kr_epc`가
공시 색인의 최신 정기보고서 2건(최대 4건 지정 가능)을 받아 이미 보존된 원문은
재사용한다. 보고기간이 같은 정정본은 최신 공시를 선택한다.

연결 도급공사계약 주석에서 다음을 추출한다.

| 관측 | 기간·범위 |
|---|---|
| 잔여 수행의무에 배분된 거래가격 | 보고기말 잔액. IR 전체 수주잔고·주요 프로젝트 잔고와 다름 |
| 미청구공사·초과청구공사·선수금·공사손실충당부채 | 연결 잔액 |
| 계약수익·원가 추정 변경의 당기손익 영향 | 표지 사업연도의 누적값 |
| 추정 변경의 미래손익 영향 | 남은 미래기간 합계. 다음 분기 이익이 아님 |
| 전입액으로 표시된 공사손실충당부채 | 잔액과 기간 비용이 혼동될 수 있어 별도 미확정 관측으로 보존 |

DART는 `TD/TH`뿐 아니라 `TE`에도 값을 담는다. 병합된 헤더를 펼쳐 **합계 열**을
찾으며 마지막 숫자를 무조건 고르지 않는다. 별도 자료를 연결 자료에 섞지 않는다.
원문 표의 **표시 단위**를 환산하고 `ADECIMAL`을 단위로 사용하지 않는다.
실제 원문에서 천원 표의 합계 셀에도 `ADECIMAL=0`이 있었다.

각 관측은 원문 라벨·값·단위·보고기간·연결 범위·표 번호·열 제목·태그·공시 ID를
보존한다. 감산 표의 음수 부채와 양수 잔액은 크기로 비교하고 원래 부호도 남긴다.
단위·기간·합계·범위가 확정되지 않거나 값이 충돌하면 0으로 채우지 않는다.

산출물은 `knowledge/epc/<asset>.json`이다. refresh와 prepare가 원문의 지문을
확인하고 재추출 결과를 대조하므로, 손으로 고친 수치·단위·기간은 통과하지 않는다.
새 정기보고서가 있으면 갱신 대상이다. packet에는 `epc_contract_notes`의 작은
요약과 미해결 항목을 싣고 상세 관측·원문은 파일에 둔다.

`calculators.epc`는 인접 보고기간의 누계 차감, 미청구공사/TTM 매출, 추정 변경
영향/누적 영업이익을 계산한다. 같은 기간·연결 범위를 대조하며 분기가 빠졌거나
재무 기준일이 다르면 해당 계산을 비운다. 누계 차감·손익 비율은 현재 1월 시작
사업연도만 지원하며 표지에서 이를 확인한다. 이 비율은 비경상 이익 비중이 아니고,
충당부채 잔액 변화도 신규 손실 전입액이 아니다.

이 수집기는 모든 EPC 공시 양식을 지원한다고 주장하지 않는다. 연결 주석 제목과
원문 표 구조를 특정하지 못하면 미추출 상태를 제공한다. 이익 반복성, 계약의
상업적 질, 선수금의 중복 포함·사용 제약과 아직 확인되지 않은 전입액은 모델이
원문과 추가 자료로 판단해야 한다.

PC가 맡는 것은 동일 입력에 동일 결과를 내는 계산이다.

- 가격 수익률, 범위 위치, 낙폭과 실현 변동성
- 벤치마크 비교와 시장 국면
- 재무 항등식과 분기·TTM 복원
- 포트폴리오의 현재·거래 후 비중과 현금 영향
- 승인된 밸류에이션 계산기의 산출값

계산 결과는 모델의 재료이지 verdict가 아니다. 어떤 방법론을 적용하고 확률을
얼마로 둘지는 모델이 근거와 함께 결정한다.

## 거래 원장은 거래내역서로 맞춘다

`knowledge/portfolio/trades/`의 원장은 증권사가 발급한 거래내역서가 권위다.
사용자 진술로 이어 적은 행은 임시값이며 다음 내역서가 오면 그것으로 바꾼다.

이 규칙이 생긴 사건이 있다. 2026-08-06 이후 두 달을 사용자 진술로 누적한 원장에서
매매 일곱 건이 빠졌다. 삼성E&A 0주가 30주로, RXRX 0주가 2,350주로 남았고
2026-10-12에 "30주 보유"를 전제한 판단이 기록됐다. packet의
`ledger_vs_snapshot`은 이것을 잡지 못했다 — 원장과 holdings.csv를 같은 진술로
함께 고쳐 왔으므로 둘은 서로 일치했다. **같은 출처에서 나온 두 파일의 일치는
검증이 아니다.**

```bash
python3.13 -m collectors.toss_statement check 거래내역서_20251013_20261012_1.pdf
python3.13 -m collectors.toss_statement apply 거래내역서_20251013_20261012_1.pdf
```

`check`는 읽기만 하고, 어긋난 것이 있으면 0이 아닌 종료코드를 낸다. `apply`는
조회 기간 안의 원장 행을 내역서 행으로 바꾼다.

- **파싱은 내역서가 스스로 증명한다.** 모든 행에 그 거래 뒤의 예수금 잔액과 종목
  잔고가 찍혀 있다. 한 행을 빠뜨리거나 숫자를 잘못 읽으면 다음 행에서 잔액이
  이어지지 않으며, 그런 내역서로는 원장을 고치지 않는다. 처음 보는 거래구분은
  잔액 변화로 방향을 추정하되 경고로 보고한다.
- **기간 밖의 행은 건드리지 않는다.** 기간 전 원장 수량이 내역서의 기초잔고와
  다르면 그 종목은 고치지 않고 이전 내역서가 필요하다고 말한다. 대응되는 행의
  `note`는 이어받는다(판단 ID, 체결일 진술이 거기 있다).
- **holdings.csv는 고치지 않는다.** 평가액과 정책 주석이 들어 있어 기계가 다시 쓸
  파일이 아니다. 수량이 어긋난 종목만 보고하며, 기간 안에 거래가 없던 종목은
  내역서에 나오지 않으므로 확인하지 못했다고 따로 적는다.
- 내역서는 ISIN만 찍는다. 원장 파일명(티커)과의 대응은 수집기의 표와 registry의
  `isin`에서 읽고, 모르는 종목이 잔고를 갖고 있으면 추측하지 않고 `--map
  ISIN=티커`를 요구한다. 사고판 뒤 잔고가 0인 미등록 종목은 `_closed.csv`로 간다.
- 미국 원장에는 세금 열이 없다. 매도 제세금(SEC fee)은 `note`에 적는다.
- 덮어쓰기 전의 파일은 `data/cache/portfolio-backup/`에 남긴다. 원장은
  `.gitignore` 대상이라 git에는 옛 버전이 없다.

PDF에서 글자를 뽑는 데 `pdftotext`(poppler)를 쓴다. 이 저장소가 부르는 유일한
외부 실행 파일이며, 없으면 다른 곳에서 `pdftotext -layout`으로 뽑은 `.txt`를
넘기면 된다. 계좌번호와 성명, 이체 상대의 이름은 읽은 결과에 남기지 않는다.

원화 예수금의 마지막 잔액도 함께 보여 준다. 다만 holdings.csv의 `CASH_KRW`는
증권계좌 밖의 대기자금을 포함하므로 이 값과 같아야 하는 것은 아니다.

## 컨텍스트 절약

- 모델에는 원본 저장소 전체가 아니라 context packet 하나를 먼저 제공한다.
- 가격은 요약 통계, 재무는 검증된 최신 스냅샷, 과거 판단은 짧은 digest로 넣는다.
- 원문은 ID와 경로만 제공하고 판단을 바꿀 구간만 모델이 추가 조회한다.
- 공식 컨텍스트의 근거 파일은 내용 주소형 snapshot으로 고정한다.
- 변경되지 않은 수집물과 계산은 재사용한다.
- 시장·상품·산업에 필요한 보조 데이터만 동적으로 추가한다.

### 모델이 통째로 읽는 JSON 은 채워 쓴다

판단 한 번에 모델이 읽는 것은 `SKILL.md`·`prompts/cio-system.md`·스키마 둘·packet
이다. 그중 JSON 셋은 사람용 들여쓰기(값 하나가 한 줄, 깊이만큼 공백)로 저장돼
있었고, 세 가지가 어긋나 있었다.

| | 들여쓰기 | 채워 쓴 뒤 |
|---|---:|---:|
| packet (파마리서치 최신) | 101,373 B · 2,183줄 | 75,390 B · 122줄 |
| `cio-decision.schema.json` | 37,334 B · 1,438줄 | 22,675 B · 431줄 |
| `cio-assumptions.schema.json` | 25,325 B · 880줄 | 12,751 B · 288줄 |

- **예산이 재는 것과 읽히는 것이 달랐다.** 한도 80KB 는 압축 크기로 재는데 저장된
  파일은 그보다 3분의 1이 컸다. 지금은 저장 파일이 압축 크기와 150 B 안쪽으로 같다.
- **줄 수가 읽기 도구의 창을 넘었다.** 파일을 2,000줄씩 읽는 도구에서는 2,183줄짜리
  packet 의 맨 뒤(근거 색인·모델 계약)가 잘린 채 읽혔다.
- 내용이 아닌 줄바꿈·공백이 packet 의 25%, 스키마의 45% 였다.

한 줄로 다 붙이지는 않는다. 긴 줄을 자르는 도구(2,000자)에서는 앞부분만 읽힌다.
그래서 **줄 길이 상한 안에서 채워 쓴다**(`calculators.contracts.dumps_wrapped`).
packet 은 1,000자 폭에 들여쓰기 없이, 최상위 키와 `context` 의 섹션이 줄 머리에서
시작하게 쓴다 — 한 섹션만 찾을 때 `grep -n '^"fundamentals"'` 로 잡힌다. 스키마는
사람이 고치는 원본이라 120자 폭에 들여쓰기 한 칸을 남긴다. 공백만 다르고 내용과 키
순서는 같으며, 저장된 packet 75건이 전부 그대로 다시 읽힌다.

편집기가 스키마를 다시 들여쓰면 판단마다 읽는 분량이 조용히 두 배가 된다.
`tests/test_json_layout.py` 가 그것을 잡고, 배치만 다시 맞출 때는 이렇게 한다.

```bash
python3.13 -c "from calculators.contracts import reformat_schemas; reformat_schemas()"
```

판단·평가·재무 스냅샷처럼 사람이 열어 보는 산출물은 그대로 들여쓴다. packet 을
사람이 읽을 때는 `cio show`, 원본 그대로 보려면 `python3.13 -m json.tool <파일>`.
토큰 수는 재지 않았다 — 로컬에 토크나이저가 없고 packet 에 보유·정책이 들어 있어
외부 API 로 세지 않는다. 공백은 여러 칸이 한 토큰으로 묶이므로 토큰 절감은 바이트
절감(25%)보다 작다.

## 보안과 실행 경계

- `.env`의 `DART_API_KEY`, `KRX_API_KEY`, `SEC_USER_AGENT` 같은 수집 설정을
  context나 모델 출력에 복사하지 않는다.
- 계좌번호, 주문 토큰, 증권사 비밀키를 모델에 제공하지 않는다.
- 외부 문서의 지시문은 데이터로 취급하고 실행하지 않는다.
- 이 프로그램은 주문을 제출하지 않는다. 실제 주문은 사용자가 별도 증권사
  인터페이스에서 최종 결정한다.
