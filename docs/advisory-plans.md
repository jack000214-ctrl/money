# 조건부 배분 계획과 기업행동

이 기능은 사용자가 읽는 배분 제안의 금액·조건·주식 기준을 보존한다.
주문·체결·계좌 상태를 관리하지 않으며 실제 주문 여부는 사용자가 결정한다.

## 미래 배분을 기록하는 작은 계약

분할매수를 제안할 때 decision의 선택 필드 `entry_plan`을 사용한다. 숫자 계획을
설명 문장에만 적지 않는다. `proposed_trade.amount`는 현재 제안액이며,
`entry_plan`은 **그 금액을 제외한 미래 배분**이다. 현재 제안액과 모든 미래 단계의
예산 합계가 packet의 사용자 예산을 넘으면 거부한다. 외부 계산기의 별도 예산을
신뢰하지 않고 저장된 질문에서 상한을 읽는다.

```json
{
  "currency": "KRW",
  "reference_basis": "질문 시점의 보통주 1주 기준",
  "reference_date": "2026-09-08",
  "stages": [{
    "stage_id": "first",
    "name": "실적 확인 후 첫 배분",
    "budget": 1000000,
    "reference_price": 40000,
    "share_multiplier": 1,
    "requires_review": true,
    "condition": "다음 실적 원문을 확인하고 모델이 성장 가정을 유지할 때",
    "cancel_if": "모델이 성장 가정을 폐기하면 취소",
    "valid_from": "2026-09-08",
    "valid_until": "2026-12-31"
  }]
}
```

위 값은 설명용이다. 가격·금액·조건·유효기간을 프로그램이 추천하지 않는다.
현재 구현은 동일 통화의 예산과 가격을 받는다. KRW 예산과 USD 가격을 직접
나누지 않으며, 그런 계획은 날짜가 있는 환산 근거를 마련한 같은 통화 질문으로 만든다.

각 단계의 `reference_price`는 질문일의 주식 단위다. `share_multiplier`는 해당 단계의
호가 단위에 대응하는 주식 수 배수다. 계산기는 호가를 기준가격/배수로, 정수주 수량을
예산/호가의 내림으로 계산한다. 배수가 1이 아니면 `capital_source_id`를 packet의
증자 원문에 연결해야 하고, 실제 권리 반영의 모델 확인도 필요하다.

`show`는 저장된 계획을 재계산해 예산·가격·수량·조건·남는 금액을 표시한다.
다음 packet은 최근 계획을 그대로 전달한다. 길이 예산 때문에 원문을 실을 수 없으면
내용 지문이 붙은 `entry_plan_ref`로 보존하고, 검증기는 그 파일의 신원과 내용을 확인한다.
과거 판단은 새 계획 필드가 없어도 유효하며 기존 문장을 임의로 새 계획으로 변환하지 않는다.
중간 판단이 새 계획을 내지 않았으면 가장 최근의 유효한 분할 제안을 참조로 남긴다.
이는 계속 매수하라는 지시가 아니며, 모델이 당시 조건과 이후 확인·취소 기록을 다시 볼 자료다.

## 조건을 확인한 기록과 가격 관측

다음 판단에서 확인한 조건은 `entry_plan_checks`에 기록한다.
`assessment_id`, `stage_id`, 원래 `condition`과 `state`, `note`, `evidence_refs`를 받는다.
상태는 `SATISFIED`, `NOT_SATISFIED`, `UNVERIFIABLE`, `CANCELLED`다. 확인불가 이외의
상태는 등록된 근거가 필요하다. 원래 조건을 다른 문장으로 바꾸거나 같은 단계를
중복 정산할 수 없다. 모델이 계획을 수정하고 싶으면 새 계획을 기록한다.

모든 과거 단계를 매번 정산하도록 강제하지 않는다. 조건의 중요성과 충족 여부는
모델이 판단한다. 다만 확인 기록이 없으면 프로그램은 충족되었다고 가정하지 않는다.
숫자 조건도 모델이 선택한 조건이며, 일반적인 자동 매수 기준으로 승격하지 않는다.

`score`는 단계별 가격 접촉과 **모델의 조건 확인이 기록된 뒤**의 가격 접촉을 나눠
표시한다. 일봉으로 같은 날의 사건 순서를 알 수 없으므로 확인 기록은 다음날부터
가격 대조에 사용한다. 뒤늦게 확인한 실적으로 과거의 싼 가격을 소급 활용하지 않는다.
무상 전후 주식 단위가 가격 시계열과 맞지 않으면 확인 불가다.

이 출력의 실제 집행 상태는 `UNKNOWN`, 전체 전략 수익률은 null이다. 조건 확인 후
지정한 가격에서 시작했다면 어땠는지의 수익률은 반사실 관측으로만 표시한다.
단계별 확인을 전부 실제 체결로 바꿔 가중 전략 성과를 만드는 기능은 없다.
기존 질문가·고정기간·벤치마크 비교의 계산 기준은 바꾸지 않는다.

## 한국 증자 공시의 산술

`python3.13 -m collectors.kr_capital ASSET`는 최신 주요사항보고서의 보통주 유상·무상
서식 필드를 추출한다. `refresh`에 기본 보조 작업으로 연결되어 있다. 원문의 회사
고유번호·접수번호·내용 지문과 재추출 결과를 대조한다. 정정 비교표의 옛 숫자를
본 공시의 값으로 사용하지 않고, 날짜가 별도 표에 있는 양식도 연결한다.

발행 전후 주식 수, 무상배정비율·배정대상 주식 수, 예정·확정 발행가격, 배정·청약·
납입·상장 예정일이 packet의 `capital_changes`에 들어간다. 최신 정정·철회 공시가
나오면 기존 추출은 갱신 대상이다. `POST_*` 분모는 공시된 계획의 시나리오다.

**예정일이 지났다고 완료로 바꾸지 않는다.** 실제 청약권 소유, 납입·입고 완료,
전환사채의 상환 또는 전환은 이 서식만으로 확인되지 않는다. 근거가 없으면 null과
미확인 항목을 유지한다. 현금 증자 발표를 현재 현금에 더하지 않고, 미래 주식 수를
현재 보유수량에 적용하지 않는다. 정확한 권리락일도 배정기준일에서 임의로 역산하지 않는다.

지원 범위는 명시된 DART 유·무상증자 서식이다. 모든 한국·미국 기업행동이나 여러
독립적인 증자 계획을 하나의 완전한 현재 자본표로 복원한다고 주장하지 않는다.
미지원 서식은 `UNSUPPORTED`이며 모델의 별도 확인이 필요하다.

EPS의 이익·주식수·가격 단위 연결은 [가정 검토](assumptions.md)의 `earnings_basis`를
사용한다. 전망은 모델이 정하고, 프로그램은 그 전망에서 입력 EPS가 계산되는지만 검사한다.
