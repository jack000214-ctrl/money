# Personal CIO

한·미 주식과 ETF에 대해 다음 질문에 답하기 위한 개인용 시스템이다.

> 이 종목을 이 가격에 이 금액만큼 사면 승리할 가능성이 있는가? 기대수익은
> 얼마이며, 나라면 얼마에 들어가고 어디서 손절·분할매도·재검토할 것인가?

좋은 모델일수록 더 나은 판단을 하도록 데이터와 과거 평가를 로컬 자산으로 남긴다.
GPT와 Claude를 포함한 모델은 교체할 수 있고, 같은 컨텍스트와 출력 계약을 사용한다.

## 역할

| 주체 | 책임 |
|---|---|
| 사용자 | 종목·검토 가격·사용 가능 금액을 고르고 실제 주문을 최종 결정한다 |
| 로컬 PC | 공식 데이터 수집, 저장, 결정론적 계산, 신선도·스키마·산술 검증을 맡는다 |
| 모델 | 부족한 정보를 조사하고 투자 방법론·확률·가격 계획·최종 투자 판단을 만든다 |

PC의 `validation = PASS | BLOCKED`는 **데이터 준비 상태**다. 모델의
`verdict = BUY_NOW | WAIT | AVOID | INSUFFICIENT`가
**투자 판단**이다. 둘을 합치거나 PC 검사 결과를 모델 판단처럼 표현하지 않는다.
실제 주문 기능은 없으며 모델도 증권사 자격증명에 접근하지 않는다.

PC는 종목의 좋고 나쁨을 판단하지 않는다. 대신 근거의 무결성·시점·누락과 사용자가
정한 위험 한도 위반을 **기계적으로** 검사한다. 이 둘은 다르다 — 앞은 판정이고
뒤는 부등호 비교다.

널리 쓰이는 가치평가 방법과 관행적인 가정을 활용할 수 있다. PER·DCF 등의 계산은
Python으로 재사용하고, 모델은 해당 자산에 맞는 방법과 성장률·배수·할인율·확률을
선택한다. 관행에서 가져온 값도 적용 이유와 재검토 조건을 남기고, 결론을 좌우하면
대체 가정으로 계산한다. 프로그램이 이런 값을 몰래 채우거나 매수·매도를 확정하지 않는다.
공시값·단위·명시된 사용자 한도는 검사하며, 제도 규칙은 출처·시행일·적용 범위를 남긴다.
자세한 구분은 [가정 검토](docs/assumptions.md#관행을-사용하는-법)에 있다.

## 빠른 시작

Codex 개인 스킬로 등록하려면 다음을 한 번 실행한다. 프로젝트의 정본 디렉터리를
연결하므로 개선 내용이 설치본에도 바로 반영되고 개인정보를 복사하지 않는다.

```bash
python3.13 skills/decide-investment/scripts/install.py
```

등록 후 `$decide-investment`로 사용한다. 다른 작업 폴더에서도 설치된 스킬의
`scripts/run.py`가 프로젝트 루트에서 CIO 명령을 실행한다.

기준 런타임은 Python 3.13.12다. 프로젝트 실행에는 외부 Python 패키지가 필요하지
않는다. 저장소 루트에서 등록 자산과 필요한 수집 작업을 확인한다.

```bash
python3.13 -m cio assets
python3.13 -m cio refresh 005930
```

필요한 기본 수집을 실행한다. `--optional`은 해당 자산에 등록된 보조 수집기까지
포함한다.

```bash
python3.13 -m cio refresh 005930 --run --optional
```

모델이 "이 종목이 좋은가"를 판단해도 "그래서 내 돈 얼마를 쓰는가"는 사용자만 아는
한도 위에서만 답할 수 있다. 그 한도는 `config/investor-policy.json`에 있고 매
컨텍스트에 실린다. 비어 있는 항목은 **제한 없음이 아니라 아직 정하지 않음**이며,
그 공백이 결론에 걸리면 모델은 `action.direction = UNDETERMINED`로 답한다.

```bash
python3.13 -m cio policy          # 정한 한도와 아직 정하지 않은 한도
```

**이것은 사람이 보는 화면이지 판단 절차가 아니다.** 모델이 쓰는 값은 전부
`prepare`가 패킷의 `investor_policy`에 싣고, 거기엔 이 화면에 없는 산술까지 있다
(각 한도의 `now`·`breach_now`·노출). 이 명령이 따로 있는 이유는 둘뿐이다 — 종목을
고르지 않고도 한도를 볼 수 있고, 정책 파일이 없거나 깨졌을 때 0이 아닌 종료코드를
낸다. 판단 전에 이것을 돌리든 말든 결론은 같다.

프로그램은 이 값을 **대조만 하고 정하지 않는다.** 한도 초과 여부는 부등호 비교의
결과일 뿐 매도 지시가 아니며, 비어 있는 한도를 그럴듯한 기본값으로 채우지도 않는다.
채우는 순간 그것은 사용자의 정책이 아니라 프로그램의 가정이 되고, 그 사실이
출력에서 사라진다. 파일에는 최대 손실액·목표수익·계좌 유형이 들어가므로 보유
내역과 같이 `.gitignore` 대상이고, 구조는 `config/templates/investor-policy.json`이
버전 관리한다. 판단 시점의 실제 정책은 `knowledge/evidence/`에 내용 지문으로
봉인되므로 재현성은 잃지 않는다.

검토 가격과 최대 사용 금액으로 모델용 최소 컨텍스트를 만든다.

```bash
python3.13 -m cio prepare 005930 \
  --price 185000 \
  --amount 5000000 \
  --amount-currency KRW \
  --intent NEW_BUY \
  --verbatim "2일 연속 하락해서 매력적인데 200~300 사볼까? 실적도 1860프로 나왔더만" \
  --claim "2일 연속 하락했다" \
  --claim "이번 실적발표가 1,860% 나왔다"
```

보유분을 어떻게 할지 묻는 것은 **다른 질문이고 다른 입력을 받는다.** 가격과
최대 투입예산 대신 원장의 최신 보유수량과 검토 수량을 받으며, 매수 예산은
받지 않는다.

```bash
python3.13 -m cio prepare 214450 --price 399500 --intent TRIM_REVIEW --quantity 30
python3.13 -m cio prepare 214450 --price 399500 --intent TRIM_REVIEW --target-quantity 60
```

질문에 보유수량·평단을 직접 제시했다면 `--held-quantity`·`--average-cost`로
이번 분석의 조건을 보존한다. `--quantity`는 보유수량이 아니라 **검토 매도수량**이다.

```bash
python3.13 -m cio prepare 028050 --price 50000 --intent HOLD_REVIEW \
  --held-quantity 100 --average-cost 45000 --verbatim "100주 보유 중인데 팔까?"
```

평단 통화의 기본값은 자산 통화다. 미국 주식을 원화 평단으로 제시했다면
`--average-cost-currency KRW`를 명시한다. 아래 가격은 사용 예시다.

```bash
python3.13 -m cio prepare RXRX --price 5 --intent HOLD_REVIEW \
  --held-quantity 100 --average-cost 6000 --average-cost-currency KRW \
  --verbatim "100주, 평단 6000원으로 들고 있는데 팔까?"
```

원화 취득원가는 그대로 보존하고 기준일이 있는 환율로 현재 평가액·원화 손익을
계산한다. 현재 환율로 과거 달러 취득평단을 만들어 내지 않는다. 반대로 달러 평단만
있으면 달러 손익은 계산할 수 있지만 실제 원화 취득원가·손익은 알 수 없다.

이 입력은 실제 잔고 확인이나 원장 갱신이 아니다. 원장과 다른 값은 함께 표시하고,
이번 보유분의 평가손익만 계산한다. 계좌 현금·총자산·비중은 자금 출처를 모르므로
비워 둔다. 사용자가 실제로 가진 수량인지와 별개로 제시한 시나리오는 분석할 수 있다.

두 질문을 하나의 "이 가격에 살까"로 정규화하면 분할매도를 묻는 packet이 매수
사다리를 만든다. 실제로 그랬다 — `TRIM_REVIEW`로 물었는데 질문은 "이 가격과
금액으로 매수하면…"이었고 803주 매수 계획이 함께 실려 나갔다. **묻지 않은
질문에 답을 만들어 주면 모델은 그 답을 근거로 받아들인다.**

`--verbatim`과 `--claim`은 **분석의 전제가 아니라 검증 대상으로** 실린다. 사용자는
이미 사고 싶은 상태에서 묻고, 강한 모델일수록 그 프레이밍을 정교하게 보강한다.
그래서 원문은 넣되 미확인 주장으로 라벨을 붙여 넣고, 모델은 각 주장을 확인·반박·
확인불가 중 하나로 닫아야 판단이 저장된다. 사용자의 전제가 틀렸다고 말해 주는 것이
전제를 정교하게 보강해 주는 것보다 값어치 있다.

닫을 때는 **무엇을 어느 기간에 무엇과 비교했는지**와 **어느 갈래의 자료로
확인했는지**를 함께 적는다. 초판은 근거 목록이 비어 있지 않은지만 봤고, 그래서
"영업이익 1,860%"를 가격 CSV로 확인했다고 적거나 존재하지 않는 근거 ID를 적는
것이 통과했다. 가격 시계열에 영업이익이 없다는 것은 투자 판정이 아니라 파일을
열어 보면 아는 사실이므로 PC가 대조한다.

생성된 `knowledge/contexts/<asset_id>/<context_id>.json`을
`prompts/cio-system.md`와 함께 원하는 모델에 제공한다. 모델은
`schemas/cio-decision.schema.json`에 맞는 JSON 하나를 반환해야 한다.

모델 출력을 `decision.json`으로 저장했다면 읽기 전용 검증을 할 수 있다. 공식
시도는 `record`가 다시 검증한 뒤 유효 판단 또는 실패 출력으로 남긴다.

새 판단은 가정의 근거와 대체 계산도 남긴다. 모델이 EPS·배수·확률·DCF 가정과
검사 범위를 정하고, PC가 민감도와 목표수익률 경계값을 계산한다. 그 결과에서
판단을 유지할지 바꿀지는 모델이 답한다.

```bash
python3.13 -m cio assumptions data/decision-assumptions.json --context CTX-...
python3.13 -m cio assumptions ASM-... --asset 028050 --json
```

계산과 근거는 해당 context에 결속된다. 판단의 `assumption_review`가 계산 ID와
모든 검사에 대한 모델의 해석을 인용하며, 다음 packet과 `show`에서도 확인할 수
있다. 입력 형식·예제·지원 범위는 [가정 검토](docs/assumptions.md)에 있다.

```bash
python3.13 -m cio validate decision.json  # 선택: 쓰기 없는 사전검사
python3.13 -m cio record decision.json
```

저장한 판단은 사람이 읽을 수 있게 펼쳐 본다.

```bash
python3.13 -m cio show 005930           # 살아 있는 것 중 최신
python3.13 -m cio show 005930 --id CIO-319aa4b74a186eea9544
```

**이 화면은 아무것도 판정하지 않는다.** 모델이 쓴 값을 자리에 놓을 뿐이며
임계값·등급·"싸다/비싸다"를 여기서 만들지 않는다. 화면이 판정을 내기 시작하면
다음 판단의 모델이 그것을 근거로 받아들이고, 그 순간 판단의 주체가 조용히
바뀐다.

무효화 신호와 가장 강한 반대 논지를 결론과 같은 크기로 놓고 `unknowns`를 접지
않는 것도 규칙이다. `risk.stop_style`이 `THESIS`면 **무효화 신호가 유일한 매도
규율**이라 — 가격 손절이 없으므로 — 그 신호를 아무도 읽지 않으면 안전장치가
통째로 없는 것과 같다. 같은 이유로 승률·확신도를 verdict 옆에 붙인다. 잘 정리된
화면은 승률 45%를 확신처럼 보이게 한다.

그래서 각 신호는 관측 조건만이 아니라 **그때 무엇을 할지**를 함께 담는다 —
`EXIT`·`TRIM_HALF`·`REASK` 중 하나를 지금 미리 정한다. 행동을 나중에 정하면 늦기
때문이다. 신호가 실제로 켜지는 날은 가격이 이미 무너진 날이고, 그날 다시 돌린
역산은 낮아진 가격에서 시작하므로 **"더 싸졌다"가 기계적으로 도출된다.** 손절가
10,000원짜리 판단이 정작 10,000원에 닿았을 때 20,000원부터 분할매도하라는 답으로
바뀌는 경로가 그것이다. 다음 판단은 `prior_signal_checks`로 그 약속을 하나씩 닫아야
하고, 약속과 다르게 행동하려면 사유를 남겨야 한다. 과거 판단의 주된 용도는 회고와
개선이며, 결론·가격선·가정은 언제든 버릴 수 있다. 새 사실뿐 아니라 과거 해석의
오류나 더 적합한 방법론도 변경 이유다. 유지할 때도 현재 근거를 설명한다.

지금 제안하는 매도 수량·지정가는 `action`에, 그 뒤의 분할매도는 선택 필드
`exit_plan`에 단계별 수량·가격·조건으로 남긴다. 합계는 보유수량과 대조하며,
사후 평가는 지정가의 가격 접촉만 관측한다. 실제 체결은 확인 자료가 없어
`UNKNOWN`이다. [계획 계약](docs/advisory-plans.md#미래-분할매도-계획).

가격 문턱은 시간을 보지 않는다. 24개월치 수익의 절반을 이틀에 받아도 분할매도가는
켜지지 않고, packet에는 그 사실을 담을 자리가 없었다. `pace_since_decision`이 그
공백을 메운다 — 판단 이후 실현 수익이 평가 기간의 어느 지점에서 나왔는지, 그리고
같은 기간에 사용자의 목표 연수익률이 냈을 값의 몇 배인지다. 목표와 주가 수익률의
통화가 같을 때만 배수를 계산하며, 다르면 환율을 추정하지 않고 비워 둔다.
**문턱이 아니라 관측이며, 몇 배부터 무엇을 하라는 규칙은 여기 없다.**

가격 이력이 쌓인 뒤 과거 판단을 사후 평가한다.

```bash
python3.13 -m cio score 005930
```

`score`는 **폐기된 판단도 채점한다.** 폐기의 뜻은 "근거로 인용하지 않는다"이지
"그런 예측을 한 적이 없다"가 아니다. 채점 계약은 인용 계약보다 작다 — 그때 무엇을
예측했는지만 남아 있으면 맞았는지는 계산된다. 둘을 하나로 묶으면 계약을 조일 때마다
track record가 통째로 사라지고, 그것은 모델이 좋아질수록 강해지는 시스템의
정반대다. 평가 결과에는 `source: LIVE | RETIRED`가 붙어 두 통이 섞이지 않는다.

모든 평가에는 모델이 스스로 정한 기간과 **무관한** 고정 기간 수익률(1·3·6·12·24개월)과
기준지수 대비 초과수익이 함께 계산된다. 모델이 기간과 승패 문턱을 직접 고르면
모델마다 다른 사건을 예측하게 되어 나란히 비교할 수 없고, 쉬운 문턱을 고르는 것만으로
점수가 좋아지기 때문이다.

`record`는 유효한 판단을 `knowledge/assessments/`에 저장한다. 유효하지 않은 모델
출력은 깨진 JSON까지 버리지 않고 `knowledge/quarantine/`에 격리한다. `score` 결과는
`knowledge/evaluations/`에 **판단당 최신 한 건씩** 남는다. 재채점하면 옛 평가를
지우는데, 평가는 판단과 가격에서 언제든 다시 만들어지는 파생물이기 때문이다.
지우지 않으면 "이 판단의 평가"가 여러 개가 되고 읽는 쪽마다 고르는 규칙이
달라진다. 판단 자체는 파생이 아니므로 절대 지우지 않는다.

packet은 **살아 있는 판단 최대 3건에 스칼라 다섯 개**만 싣는다
(`latest_evaluation`). 채점 이력 전체를 넣으면 예산을 먹고 대부분의 판단에서
읽히지도 않는다. 그러나 "내가 같은 실수를 반복하는 중인가"를 묻고 싶을 때
꺼낼 자리는 있어야 한다. 원문에 대해 `search`가 하는 역할을 채점에 대해서는
`evals`가 한다.

```bash
python3.13 -m cio evals 214450           # 판단별 최신 채점
python3.13 -m cio evals 214450 --plan    # 그때의 진입·손절·분할매도 문턱까지
```

`--plan`이 있는 이유는 실제로 그 열에서 결함이 보였기 때문이다. 12일간 판단
11건의 `preferred_entry`가 그날 시세와 상관계수 +0.827로 움직였다 — 가치
추정이 아니라 "오늘 가격 −14%"였고, 진입 밴드가 실제로 충족된 두 번 모두 새
판단이 밴드를 더 아래로 내렸다. **문턱을 세로로 놓고 보기 전에는 아무도 그것을
못 봤다.**

판단 계약을 조이면 그 이전 판단이 재검증에 실패해 다음 컨텍스트로 이어지지
않는다. 파일은 남아 있으므로 **직접 열어 본 사람과 패킷을 읽는 모델이 서로 다른
것을 보게 된다.** 어떤 판단이 살아 있고 무엇이 끊겼는지 먼저 확인한다.

```bash
python3.13 -m cio retire 214450          # 살아 있음 / 계약 미달 / 폐기됨
```

더 못 믿을 판단은 명시적으로 폐기한다. 자동으로 치우지 않는 이유는 계약 미달이
결론이 아니라 사고이기 때문이다. 폐기한 판단은 지우지 않고
`knowledge/retired/`로 옮겨 사유와 함께 남기며, 이후 컨텍스트에는 **있었다는
사실만** 실린다 — verdict·가격계획·논지는 인용할 수 없게 빠진다. 폐기 사유도
packet에는 첫 80자만 싣는다. 사유에 옛 지정가·논지를 길게 적는 일이 쌓여 12건에
17.5KB(예산의 22%)가 됐고 살아 있는 판단의 논지를 밀어냈다. 전문은 `cio retire` 화면에 있다.

```bash
python3.13 -m cio retire 214450 --reason "구버전 산물"            # 대상만 확인
python3.13 -m cio retire 214450 --reason "구버전 산물" --confirm  # 실제 이관
python3.13 -m cio retire 214450 --reason "..." --all --confirm    # 유효한 것까지
```

모델이 판단에 남긴 수집 요청은 사용자가 읽고 닫는 대기열이다. 처리되기 전까지
다음 컨텍스트에 다시 실려 나간다.

```bash
python3.13 -m cio requests 005930
python3.13 -m cio requests 005930 --resolve REQ-3e547a42822d --state DONE \
  --note "collectors/dart.py filings 배선"
```

보유 종목의 결정론적 산술은 계산기가 낸다. 평단·실현손익은 증권사 스냅샷이 아니라
거래 원장에서 이동평균법으로 접고, 검토 가격 기준 배수 환산·세 분모 비중·추가
수량별 눈금을 함께 낸다.

```bash
python3.13 -m calculators.position 214450 --price 331000
python3.13 -m calculators.position 214450 --price 331000 --add 5 10 20
```

평단은 **두 경로로 나오고 둘을 합치지 않는다** — 거래 원장의 이동평균과 스냅샷의
(평가액 − 평가손익) ÷ 수량이다. 벌어졌다면 둘 중 하나가 낡은 것이며, 어느 쪽인지는
계산기가 정하지 않고 차이만 보고한다.

**이 계산기는 판정을 내지 않는다.** 싸다·비싸다, 사도 된다·줄여라 같은 값은 출력에
없고 임계값도 여기서 정하지 않는다. 모델이 세운 문턱을 받아 대조할 뿐이다. 계산기가
판정을 내기 시작하면 모델이 그것을 근거로 받아들이고, 그 순간 판단의 주체가 조용히
바뀐다. `tests/test_position_math.py`가 그 경계를 고정한다.

일부 계산기는 **refresh 배선에 없고 손으로 부른다.** packet 을 만들지 않으므로
모델이 자동으로 받지 못하며, 결론에 쓰려면 조사 결과로 직접 인용해야 한다.

```bash
python3.13 -m calculators.peer_kr 214450 145020 214150 278470   # 한국 동종 비교
python3.13 -m calculators.sector_strength --highlight 헬스케어    # 미국 섹터 상대강도
```

`sector_strength`는 미국 섹터 ETF 11종의 SPY 대비 상대강도이며 **한국 종목의 섹터
대리가 아니다.** 상대강도는 밸류에이션 지표도 아니다 — 자금이 어디로 갔는지에 대한
관측일 뿐이고, 이 값으로 비중을 정하지 않는다. 두 계산기의 산술 경계는
`tests/test_manual_calculators.py`가 고정한다.

미국 종목은 SEC 8-K 의 Item 번호를 함께 싣는다. `primaryDocDescription` 은 거의
항상 form 코드와 같아서, Item 없이는 8-K 31건이 전부 "8-K"로만 보이고 임상 결과
발표와 임원 교체를 구분할 수 없다.

임상단계 바이오의 파이프라인은 공개 API 가 없다. 모델이 조사한 결과를 대장에
남기면 다음 판단의 packet 으로 실려 나온다.

```bash
python3.13 -m cio pipeline RXRX                       # 기록된 것 보기
python3.13 -m cio pipeline RXRX --name REC-4881 \
  --stage PHASE2 --readout 2026-11-30 --source <URL>
```

한국 종목은 다음 실적 발표일을 결산실적 공시예고 원문에서 읽어 캘린더로 만든다.
공시 색인에는 제목만 있고 발표 예정일은 본문에만 있어서, 이벤트까지 며칠
남았는지가 판단 입력에서 빠져 있었다.

```bash
python3.13 -m collectors.kr_calendar 214450
```

미국 주식은 SEC 정기보고서 원문에서 발행주식 수·주식보상·발행 관련 수치와
사업·제품·지역별 태그를 자동 추출한다. 표지 주식 수, 결산일 주식 수, EPS
가중평균 분모는 기준이 다르므로 구분해서 싣는다. `ir_sources`가 등록된 회사는
공식 IR에서 실제 실적 발표 안내를 수집하며 잠정 일정·접속 실패·미공개를
구분한다. SEC 제출 색인으로 만드는 `collectors.us_calendar`는 별도로 과거
(결산기말 → 10-Q/10-K 제출) 간격으로 정기보고서 제출일만 추정한다. 연간/분기
구분은 실제 10-K 결산월을 따르며, 회계연도를 알 수 없거나 월말이 아닌 52/53주
회계달력은 추정하지 않는다.
한국은 잠정실적과 정기보고서를 나눠 낸다. **잠정실적 공정공시는 매출·영업이익 요약만
담고 재고자산·부문별 매출은 정기보고서에만 나온다.** 정기보고서 제출일은
공시되지 않으므로 과거 (잠정 → 정기) 간격의 중앙값으로 추정하며, 분기·반기와
사업보고서는 법정 기한이 달라 따로 센다.

예외도 있다. 파마리서치는 품목군별 매출(의료기기·화장품·의약품 × 내수·수출)을
잠정실적 본문에만 적고 정기보고서에는 이 분해가 없다. 이런 회사는 `KR_PRODUCT_SALES`를
등록하면 로컬 원문에서 분기 시계열을 만들어 packet에 싣는다(합을 같은 공시의
매출액과 대조한다). [데이터 정책](docs/data-policy.md#품목군별-매출은-그-원문에서-시계열로-만든다)

```bash
python3.13 -m collectors.kr_product_sales 214450
```

모델이 조사한 원문은 인용하기 전에 로컬에 보존한다. 받은 그대로 저장하며
정제하지 않는다.

한국 EPC 기업은 연결 도급공사계약 주석을 따로 추출한다. 수주잔고의 범위,
미청구·초과청구공사·선수금·충당부채 잔액, 계약 추정 변경의 누적·미래 손익을
단위와 기간까지 보존한다. 삼성E&A에는 `KR_EPC`가 등록되어 `refresh --optional`과
packet에 연결되어 있다.

```bash
python3.13 -m collectors.kr_epc 028050
```

누적값의 인접 분기 차감과 같은 기준일 재무의 비율은 PC가 계산한다. 이익의
반복성·선수금의 성격은 모델이 판단한다. [추출 범위와 한계](docs/data-policy.md#epc-연결-도급공사계약-주석).

```bash
python3.13 -m cio snapshot <URL> --asset 005930 --label dram-price-2026q3
python3.13 -m collectors.dart document 20260730800077   # 한국 공시 원문
```

보존한 원문은 통째로 읽는 것이 아니라 필요한 자리만 찾아 쓴다. 사업보고서
하나가 100만 자라 컨텍스트에 넣을 수 없기 때문이다.

```bash
python3.13 -m cio docs 005930                  # 무엇이 있고 무엇을 안 받았나
python3.13 -m cio search 005930 "부 문 \|"     # 부문별 매출 표
python3.13 -m cio search 005930 "주요 매출처"
```

부문별 매출·비중, 주요 매출처, 수주잔고, 생산능력, 원재료 공급처, 시장점유율은
사업보고서에 있다. 회사 구조에 관한 사실을 언론 기사로 인용하는 것은 1차 출처를
두고 2차 출처를 쓰는 것이다.

컨텍스트가 참조한 근거와 prompt/schema는 내용 지문으로
`knowledge/evidence/`에 중복 없이 보존된다. 이후 원본 파일이 갱신돼도 당시 모델이
사용한 입력은 바뀌지 않는다.

## 자산별 분기

`config/assets.json`이 시장(`KR`/`US`), 상품(`STOCK`/`ETF`), 공시원,
벤치마크, 분석 렌즈와 적합한 가치평가 후보를 지정한다. 이 값은 모델의 출발점이지
결론을 강제하는 규칙이 아니다. ETF에 회사 DCF를 적용하거나 적자 임상 바이오에
정률성장 DCF를 적용하지 않는다.

새 자산은 `python3.13 -m cio register`로 등록한다. 상세 필드와 수집 정책은
[데이터 정책](docs/data-policy.md)을 참고한다.
